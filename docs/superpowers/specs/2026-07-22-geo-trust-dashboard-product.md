# GEO 可信仪表盘（Trust Dashboard）产品文档

> **文档性质**：产品规划 / 领导汇报稿（非实现说明书）  
> **状态**：草案，待评审  
> **日期**：2026-07-22  
> **归属**：GEO Suite 下一层能力（测量层），与现有「诊断 + 内容生产」并列  
> **一句话定位**：面向传媒行业的、方法可审计的 AI 搜索观测产品——把 AI 搜索变成可信仪表盘。

---

## 0. 汇报用摘要（60 秒）

**现在的 GEO Suite** 解决的是：发现页面缺口 → 按知识库生产可引用内容 → 发布与工程回看。  
**它还不能合法回答**：「我们在 AI 答案里的引用率是否真的提高了？」

> 战略差距与近程测量见：[现状距离一页纸](../../GEO-gap-vs-strategy-brief.md)、[L2 试点工程计划](./2026-07-24-l2-pilot-factcard-measurement.md)。  
> **D1 原型已落地**：GEORank 后台 `/admin/trust-obs`（单一 API 自动探针）；Suite `/suite?step=measure` 只读展示。

**拟建设的「可信仪表盘」** 专门回答这个问题：

- 用**公开的 Prompt / 探针题库**去问主流 AI 搜索；
- 声明**地区、语言、设备/客户端口径**；
- **重复采样**，并处理**答案漂移**；
- 区分 **mention / citation / recommendation / competitor co-mention**；
- 不只给一个「AI 引用分」，还要说明：**分数从哪来、为什么变了、哪些来源改变了模型答案**。

与现有能力关系：

| 层 | 现有/拟建 | 回答的问题 |
|----|-----------|------------|
| 规划与就绪 | GEORank 诊断 | 页面是否具备被理解的结构？ |
| 生产与分发 | GEOFlow + Suite | 内容是否按证据生产并发布？ |
| **测量与归因** | **可信仪表盘（本产品）** | **AI 答案里是否提及/引用我们？是否变好？为何变？** |

## 1. 背景与问题

### 1.1 市场变化

用户越来越多直接问 AI（ChatGPT、Perplexity、文心、通义、Gemini、AI Overview 等），品牌在「答案层」的可见度开始影响获客与声誉。传媒行业尤其敏感：

- 品牌/栏目/记者/报道实体是否被正确提及；
- 答案是否引用权威来源，还是引用竞品或错误来源；
- 若只给黑箱「可见性分数」，采编、法务、品牌公关都无法采信。

### 1.2 现有产品缺口（必须对内说清）

| 现有信号 | 实际含义 | 能否当「引用率」 |
|----------|----------|------------------|
| GEORank 诊断「citation」维 | 页面外链/权威链密度 | **否**（命名易误解） |
| 诊断 overall_score | 页面 GEO 就绪度 | **否** |
| GEOFlow 增长中心 AI 爬虫 PV | 可能被抓取的代理信号 | **否**（产品已有边界说明） |
| Suite「回看」 | handoff / 任务 / 发布回调 | **否**（工程闭环，非答案测量） |

**结论**：缺一整层「答案面板测量（Answer Panel Measurement）」。本产品即补这一层。

### 1.3 产品原则（汇报强调）

1. **可审计优于好看**：原始答案样本、Prompt 版本、采样参数可导出。  
2. **代理指标不得冒充结果**：爬虫 PV、页面分不得改名为「引用率」。  
3. **先分类、后打分**：taxonomy 清晰，再聚合指数。  
4. **解释变动，而不是只报涨跌**：客户要知道「为什么变了」。  
5. **合规默认**：不伪造截图、不夸大因果、不隐瞒方法局限。

## 2. 目标用户与使用场景

### 2.1 主用户（传媒）

| 角色 | 诉求 |
|------|------|
| 品牌 / 市场负责人 | 周报：我们在 AI 答案里有没有被提到、提得对不对 |
| 内容 / 采编负责人 | 哪些选题、哪类来源在改变模型答案 |
| 公关 / 法务 | 方法是否可说明、样本是否可留存、表述是否合法 |
| 增长 / SEO-GEO 运营 | 与内容改版、外链、知识库更新联动看效果 |

### 2.2 典型场景

1. **改版前后对比**：专题页 / 品牌百科 / FAQ 上线前后，同题簇引用率是否变化。  
2. **危机与纠错**：错误事实是否仍出现在 AI 答案；纠偏内容发布后多久反映。  
3. **竞品共现**：答案同时提到我方与竞品的频率与位次。  
4. **来源争夺**：模型引用的 domain 清单变化（权威媒体 vs UGC vs 竞品站）。

### 2.3 非目标（本阶段不做）

- 不承诺「操控」或「保证进入」某模型答案。  
- 不做传统网页 SEO 排名监控的替代品。  
- 不把 GEOFlow 增长中心改造成引用率看板（避免指标污染）。  
- MVP 不覆盖全部全球模型与全部语言（先定中国传媒常用场景 + 可扩展接口）。

## 3. 产品定义

### 3.1 一句话

**针对传媒行业的、合法可审计的 GEO 效果观测产品：把 AI 搜索变成可信仪表盘。**

### 3.2 价值主张（对外话术）

- **公开 Prompt 设计**：测什么题、怎么问，客户看得见、版本可追溯。  
- **地区与设备口径**：每次报告写明采样发生在什么地区、语言、客户端形态。  
- **重复采样**：同题多次，降低单次运气。  
- **处理答案漂移**：区分随机波动与结构性变化。  
- **细分类观测**：mention / citation / recommendation / competitor co-mention。  
- **可解释分数**：告诉客户分数从哪来、为什么变、哪些来源改变了模型答案。

### 3.3 成功长什么样（验收直觉）

客户打开周报能看到：

1. 各模型上「提及率 / 引用率 / 推荐率 / 竞品共现率」及置信区间或重复采样说明；  
2. 相对上周的 Δ，以及 **贡献最大的题簇与来源 domain**；  
3. 点进任意变化，能看到 **原始答案摘录 + 标注标签 + Prompt 版本**；  
4. 附录有方法论文档（可给法务）。

## 4. 核心指标体系（Taxonomy）

所有指数必须由下方标签聚合而来，禁止「无样本黑箱分」。

| 标签 | 英文 | 定义（汇报口径） | 判定要点 |
|------|------|------------------|----------|
| 提及 | **mention** | 答案文本中出现品牌/实体名，未必给来源链接 | 实体别名表；排除无关同名 |
| 引用 | **citation** | 答案给出可点击/可解析的来源，且来源指向我方（或我方内容 URL） | URL/域名归属；站点映射表 |
| 推荐 | **recommendation** | 答案将我方作为建议选项、首选或明确推荐 | 需标注规范；MVP 可先人工抽检校准 |
| 竞品共现 | **competitor co-mention** | 同一答案中同时出现我方与预设竞品 | 竞品名单可配置 |

可选扩展（二期）：

- **正确提及 / 错误提及**（事实核对，依赖知识库断言）  
- **引用位次**（第几个来源）  
- **情感 / 风险表述**（公关向）

### 4.1 聚合指标（仪表盘主数字）

对每个「品牌 × 模型 × 时间窗 × 题簇」：

- Mention Rate = 出现 mention 的采样次数 / 有效采样次数  
- Citation Rate = 出现 citation 的采样次数 / 有效采样次数  
- Recommendation Rate = …  
- Competitor Co-mention Rate = …  

**主推「引用率 Citation Rate」作为传媒对外沟通主指标**；提及率为辅；推荐率谨慎使用（主观更强）。

### 4.2 「分数从哪里来」的强制披露字段

每个指数旁必须可展开：

- Prompt 集版本 ID  
- 模型列表与调用方式（官方 API / 浏览器面板等——MVP 需选定并写死口径）  
- 地区 / 语言 / 设备或客户端类型  
- 每题重复次数 N、时间窗  
- 有效样本数、失败/拒答数  
- 标注方式（规则 / 模型辅助 / 人工抽检比例）

## 5. 方法论（可信的根基）

### 5.1 公开 Prompt 设计

- 维护 **Prompt Pack（探针包）**：按传媒场景分簇（品牌认知、栏目查询、报道实体、对比题、纠错题等）。  
- 每条探针含：题干模板、变量（品牌名、竞品名）、期望实体、禁用诱导话术说明。  
- **版本化**：`prompt_pack_id` + semver；变更写 changelog；历史报告绑定当时版本。  
- **对客户可见**：报告页可下载「本期使用的 Prompt 全文」。

MVP 建议规模：**1 个垂直包（传媒通用）约 20–30 题**，可配置品牌变量。

### 5.2 地区与设备口径

每次运行任务声明并落库：

| 字段 | 示例 | 说明 |
|------|------|------|
| region | `CN-mainland` / `HK` / `US` | 影响模型可用与答案本地化 |
| language | `zh-CN` | 与题库语言一致 |
| client_surface | `api` / `web_logged_out` / `web_logged_in` | 不同表面答案可能不同 |
| device_class | `desktop`（MVP 可固定） | 二期再扩 mobile |

报告首页用灰字展示：「本报告口径：中国大陆 · 简体中文 · API 表面 · 桌面」。

### 5.3 重复采样

- 默认：每题每模型 **N=3**（MVP 可配置 3/5）。  
- 指标按「有效完成的采样」计算；超时、拒答、安全拦截单独计入「不可观测」。  
- 报告展示点估计 + 「基于 N 次重复」说明；二期再上置信区间。

### 5.4 答案漂移处理

定义两类变化：

1. **随机漂移**：同题同口径下，短窗内答案/来源集合波动，但标签率无显著方向性变化。  
2. **结构变化**：mention/citation 标签率跨阈值显著变化，或主导引用 domain 集合发生替换。

产品行为：

- 对同题保存答案指纹（归一化文本 hash + 引用 domain 集合）。  
- 周报默认对比「本周聚合 vs 上周聚合」，并标记「高波动题」（需人工看）。  
- 避免因单日单次采样向客户宣称「暴涨/暴跌」。

### 5.5 「为什么变了 / 哪些来源改变了答案」

变动解释引擎（报告核心差异化）输出：

1. **题簇贡献**：哪些题的标签变化贡献了总 Δ。  
2. **来源贡献**：新增/消失/位次变化的引用 domain（如 `example.com` 进入 Top 引用）。  
3. **模型贡献**：变化集中在哪个模型。  
4. **样本链接**：一键打开对应原始答案与标注。

**禁止**自动写成「因为你们发了某篇文章所以引用率提高」——除非客户自己把「内容发布事件」手动关联为假设；系统只提供相关时间线（可与 GEOFlow 发布回调事件并列展示，标注为「时间相关，非因果证明」）。

## 6. 产品形态与信息架构

### 6.1 建议入口

- GEO Suite 增加步骤或模块：**「观测」 / Trust Dashboard**（与诊断、生产并列）。  
- 独立路由示例：`/trust` 或 `/suite?step=measure`（实现阶段再定）。  
- **不**塞进 GEOFlow「增长中心」，以免与爬虫 PV 混淆。

### 6.2 主要页面

| 页面 | 内容 |
|------|------|
| 总览仪表盘 | 四率趋势、模型对比、本周 Δ 摘要、口径条 |
| 题簇明细 | 按探针题查看每次采样与标签 |
| 来源分析 | 引用 domain 排行、进入/退出列表 |
| 变动解释 | 「为什么变了」叙事 + 证据链 |
| Prompt 与方法 | 公开题库、版本、口径说明（法务友好） |
| 运行与配额 | 采样任务、费用/次数、失败重试 |
| 品牌配置 | 实体别名、竞品名单、自有域名归属 |

### 6.3 与现有 Suite 的协作关系

```text
GEORank 诊断 ──缺口/选题──▶ 拓词/方案 ──handoff──▶ GEOFlow 生产发布
     │                                                      │
     │                                                      ▼
     │                                            发布事件（时间线，非因果）
     ▼                                                      │
可信仪表盘 ◀──── 同品牌题库周期采样 ◀────────────────────────┘
     │
     └──▶ 再指导选题 / 知识库补强 / 纠错内容（闭环，但是测量独立）
```

## 7. MVP 范围（建议 6–8 周可汇报演示）

### 7.1 MVP 必须有（P0）

1. 品牌配置：官方名、别名、自有域名、3–5 个竞品。  
2. 传媒 Prompt Pack v1（≥20 题）+ 版本号 + 客户可见全文。  
3. 至少 **2 个模型表面**（建议：1 个国内可用 API + 1 个国际或另一国内；最终以账号与合规可选为准）。  
4. 每题重复 N=3；地区/语言/表面口径落库并展示。  
5. 自动初标 **mention + citation**；recommendation / co-mention 规则初标 + **人工抽检队列**（抽检比例可配置，默认 10%）。  
6. 周报：四率 + Δ + 题簇贡献 + 来源进入/退出 + 原始样本抽查。  
7. 方法论文档页（固定模板）。  
8. 明确文案：本产品测量的是「面板采样下的标签率」，不是搜索引擎官方排名。

### 7.2 MVP 明确不做（P0 砍掉）

- 全自动「因果归因到某篇文章」。  
- 移动端多设备矩阵。  
- 实时分钟级监控。  
- 与增长中心 AI 爬虫 PV 加权合成「超级引用分」。  
- 大规模人工标注众包平台。

### 7.3 一期增强（P1）

- recommendation / co-mention 模型辅助标注准确率提升。  
- 置信区间与显著性提示。  
- 与 GEOFlow 发布事件时间线并排（仍标非因果）。  
- 导出 PDF/Word 客户周报。  
- 多品牌 / 多项目权限。

### 7.4 二期（P2）

- 错误事实检测（对接知识库断言）。  
- 更多模型与面板表面。  
- 客户自定义 Prompt Pack（审核后发布）。  
- API 开放给传媒集团数据中台。

## 8. 合规、合法与风险（传媒必答）

| 风险 | 应对 |
|------|------|
| 被质疑「刷指标 / 黑箱」 | 公开 Prompt、样本可导出、口径写死 |
| ToS / 抓取违规 | MVP 优先 **官方 API**；若必须面板自动化，单独立项法务评审 |
| 夸大宣传 | 销售话术白名单；禁止「保证上榜」「官方引用率」 |
| 答案含竞品/敏感 | 样本权限与留存周期；客户数据隔离 |
| 模型更新导致断层 | Prompt 与模型版本绑定；大版本变更单独出「方法变更说明」 |
| 与现有「诊断 citation」名称冲突 | 对外统一改称「页面外链就绪度」；「引用率」仅保留给本仪表盘 |

## 9. 成功指标（产品自身 OKR 建议）

**客户价值**

- 周报被品牌例会采用（质化）。  
- 客户能独立说清：「我们的 Citation Rate 如何算」。  
- 至少 1 次「内容改版前后」可解释的 Δ 案例（带样本）。

**质量**

- mention 自动标注准确率 ≥ 约定阈值（上线前用金标集验收）。  
- citation（域名归属）准确率更高阈值。  
- 抽检争议工单闭环时间。

**商业**

- 可按「品牌数 × 模型数 × 题量 × 采样频率」计价。  
- 与内容生产套件捆绑：测量订阅 + 生产席位。

## 11. 方案选项（供决策）

| 方案 | 描述 | 优点 | 缺点 | 建议 |
|------|------|------|------|------|
| **A. Suite 内独立模块** | `/trust` 挂在 GEO Suite，数据独立库表 | 品牌故事完整；与诊断/生产串联 | 要扩 Rank 后端能力 | **推荐** |
| B. 完全独立产品 | 新仓库新品牌 | 边界最清 | 两套账号与叙事 | 若法务要求强隔离再选 |
| C. 只做周报人工台 | 脚本采样 + 表格 | 最快出试点 | 难规模化、难可信自动化 | 仅作预研，不作为产品终态 |

**推荐 A**：对外仍是 GEO Suite 能力升级；对内测量数据模型独立，避免与 `diagnostic.citation_analysis`、增长中心 PV 混表。

## 12. 决策清单（会上要拍板的）

1. MVP 优先模型名单（国内/国际各几个）？  
2. 采样表面：仅 API，还是允许浏览器面板（法务）？

5. 试点客户：哪一个传媒品牌 / 栏目？  
6. 命名：产品中文名是否定为「GEO 可信仪表盘」或「AI 搜索观测」？
