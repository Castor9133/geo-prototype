# 广电数智化内容工程战略整合（草案）

> **用途**：内部汇报 / 方向对齐 / 研发优先级  
> **日期**：2026-07-24  
> **口径**：把 GEO 从「工具演示」提升为「面向智能化时代的内容工程建设」  
> **责任边界建议**：数科承担 1～2 层全部研发与平台复用；3 层为内容+创意+产品联合长期建设

---

## 0. 一句话

在智能化时代，广电要建设的不是又一个 CMS，而是一条可复用的内容工程链路：

**被找到 → 被引用 → 被信任（官媒背书）**，并以知识工程与 RAG 能力作为可复用的核心资产。

---

## 1. 四层目标（整合后的主叙事）

| 层级 | 目标 | 通俗说法 | 当前状态 | 主导 |
|------|------|----------|----------|------|
| **L1 被找到** | 大模型/答案引擎能发现我们的内容与实体 | 先进入「可见池」 | **正在做**：招 SEO、官方号运营配合 | SEO + 运营 + 数科基建 |
| **L2 被引用** | 大模型回答时愿意引用我们的来源与事实 | 成为「可引用证据」 | **接下来要做（最关心）**：强化自有 RAG / 知识工程 | **数科全研发**（可复用） |
| **L3 被信任** | 大模型在叙事上采信官媒身份与背书价值 | 成为「可信权威」 | 长期蓝海：创意型图文音视频，可被模型理解 | 内容+创意+营销+数科 |
| **L4 组织能力** | 面向数智时代的内容工程人才与机制 | 能持续迭代的队伍 | 内部培训选拔：懂营销 × 懂大模型 × 懂内容 | 组织 / 人力 / 业务 |

关系不是四条平行业务线，而是**递进飞轮**：

```text
L1 发现密度 ──▶ L2 引用质量（知识工程）──▶ L3 信任资产（创意多模态）
       ▲                    │                        │
       └──────── L4 人才与机制持续迭代 ◀───────────────┘
```

- **L1、L2**：可产品化、可复用、需持续迭代；投入相对可控，见效路径清晰。  
- **L3**：差异化与护城河所在，难、慢、贵，但不能用生硬文案硬塞；需要「人能共鸣、模型能读懂」的创意表达。  
- **L4**：保证飞轮转得起来的组织前提。

---

## 2. 各层「做什么 / 不做什么」

### L1｜让大模型能找到我们

**在做 / 要配合**

- SEO / 技术 SEO / 站点可抓取与结构化（Schema、站点地图、权威外链等）
- 官方号矩阵常态运营（不是一次性发稿）
- 内容入口统一、实体名与栏目名一致（减少模型「认不出是谁」）

**成功信号（代理指标，非最终引用率）**

- 页面就绪度、抓取可达、官方实体一致性  
- AI 相关爬虫触达、索引覆盖（代理信号，不能等同引用）

**说明**：L1 是入场券，不是护城河；没有 L2，找到了也「无料可引」。

---

### L2｜让大模型能引用我们（核心 · 数科主责）

这是**最可能改变广电在智能化时代内容模式**的一层，也是其他项目可复用的能力底座。

**能力定义**

把分散内容沉淀为：**可审计、可检索、可约束生成** 的知识工程体系，并支撑：

1. **对内**：选题 / 生产 / 审核时的证据召回（自有 RAG）  
2. **对外**：可被答案引擎引用的权威素材与结构化事实  
3. **复用**：同一套知识工程服务多个栏目、项目、广告前链路

**建设重点（与现有 GEO Suite 对齐）**

| 模块 | 作用 |
|------|------|
| 知识库 / 切片 / Embedding / 混合检索 | 证据可召回 |
| 事实卡 / 来源元数据 / 审核状态 | 引用可审计 |
| 受知识约束的内容生产（GEOFlow） | 少空写、多证据 |
| （规划中）可信仪表盘：mention / citation 测量 | 验证「引用是否真的提高」 |

**成功信号（比 L1 更硬）**

- 知识覆盖率、切片向量化率、检索命中质量  
- 生产内容「带证据比例」  
- 中期：答案面板抽样中的 **Citation Rate**（见可信仪表盘产品文档）

**边界**：L2 解决「有东西可被引、引得准」；不承诺「模型一定信官媒叙事」——那是 L3。

**投入原则**：数科有能力且愿意承担全部研发；业务侧提供语料、审核规则与运营闭环。

---

### L3｜让大模型相信我们（官媒背书 · 长期蓝海）

**目标**

用官媒身份，为品牌/广告/公共叙事提供**可被模型吸收的信任信号**——不是硬广文案堆砌，而是：

- 有创意设计的图文  
- 可被理解的音视频结构（字幕、章节、口述要点、实体对齐）  
- 符合传播规律、又能被模型解析的表达

**为何难**

- 需要营销 × 大模型机制 × 内容创意的综合人才  
- 周期长，评价不能只看 PV  
- 「生硬灌输」会被人厌，也被模型降权

**为何值得做**

这块仍是蓝海；一旦跑通「可传播 + 可被模型读取」的范式，就是差异化资产，难被纯技术团队复制。

**与 L2 的关系**

L2 提供事实与证据骨架；L3 提供信任与叙事血肉。没有 L2，L3 容易变成漂亮但不可引用的内容。

---

### L4｜组织与人才（飞轮润滑剂）

- L1/L2：可标准化、可培训、可持续迭代  
- L3：需内部选拔与培养「懂营销、懂大模型、懂内容」的复合人才  
- 机制建议：内容工程例会、知识库责任制、引用效果复盘（对接测量层）

---

## 3. 与当前 GEO Suite 工作的映射（避免两张皮）

| 战略层 | 当前/规划中的产品能力 |
|--------|----------------------|
| L1 | 诊断（页面就绪）、站点/分发、运营配合 |
| L2 | GEOFlow 知识库 / Embedding / RAG 任务生产；Rank 移交与回看；**可信仪表盘（测量引用）** |
| L3 | 尚未产品化；属内容创意与多模态生产规范，平台可后续提供「模型可读素材规范 + 发布管线」 |
| L4 | 流程、权限、培训材料、试点栏目机制 |

**汇报口径建议**

> 我们不是在买一个「AI 写作工具」，而是在建 **L2 知识工程底座**（可复用），同时用 L1 保证被发现，用长期 L3 积累官媒信任资产。

---

## 4. 节奏建议（便于拍板）

### 近程（0～1 个季度）——兑现 L2

1. 知识工程 MVP：栏目事实卡 + Embedding 召回 + 受约束生产  
2. 1～2 个试点栏目跑通「资料 → 知识库 → 文章/答案素材」  
3. 引用效果开始用「答案抽样 / 可信仪表盘」说话（即使先手工周报）  
4. L1 并行：SEO 招聘与官方号 SOP，不阻塞 L2

### 中程（2～3 个季度）——L2 产品化复用 + L3 试点

1. 知识工程平台化，服务多个项目  
2. 引用率/提及率例行复盘  
3. L3 小规模试点：选 1 条「创意型、模型可读」样板内容（图文或短视频规范）

### 远程（年度）——信任资产

1. L3 方法论沉淀（创意 brief × 模型可读清单）  
2. 复合人才梯队  
3. 广告/品牌背书场景的合规与产品边界

---

## 5. 资源与分工（整合你的原话）

| 角色 | 承担 |
|------|------|
| **数科** | L1 相关平台/诊断能力 + **L2 全部研发**；愿意作为可复用底座对外/对内赋能 |
| **运营 / SEO** | L1 持续运营与流量侧配合 |
| **内容 / 创意** | L3 创意表达；与数科共建「模型可读」规范 |
| **组织** | L4 选拔培训「营销 + 大模型 + 内容」人才 |

**投入判断（汇报可用）**

- L1、L2：**容易起步，但必须持续迭代**；ROI 相对清晰。  
- L3：**投入最大、难点最大、蓝海最大**；不急于全面铺开，应用试点证明范式。

---

## 6. 风险与原则

1. **勿把 L1 代理指标说成引用率**（爬虫 PV ≠ 被引用）。  
2. **L2 不做黑箱**：知识来源、切片、召回要可审计（契合传媒合规）。  
3. **L3 拒绝生硬灌输**：宁可慢，不做「模型垃圾内容」。  
4. **测量独立**：效果用抽样与 taxonomy 说话（见可信仪表盘文档），与生产系统解耦。

---

## 7. 建议的对外/对上标题句

> **面向数智化时代的广电内容工程：先被找到，再被引用，终被信任。**  
> 数科以可复用的知识工程与 RAG 能力扛起「被引用」这一层核心研发；「被信任」作为长期蓝海，用创意型图文音视频建设官媒背书资产，并配套复合人才培养。

## 附录 A｜现状差距评估（2026-07-24）

> **用途**：对照四层战略回答「现在距离有多远、还要补什么」。  
> **精简汇报页**：[GEO 现状距离与补齐清单](../../GEO-gap-vs-strategy-brief.md)  
> **近程落地**：[L2 试点工程计划](./2026-07-24-l2-pilot-factcard-measurement.md)

### A.1 一句话结论

现有 GEO 能演示并支撑「发现缺口 → 知识约束生产 → 发布与工程回看」；**还不能合法回答「AI 答案里的引用率是否提高」**。相对四层目标：L1 近、L2 半程（生产近、测量远）、L3/L4 远。

```text
L1 发现 ──▶ L2 知识生产（已有）──▶ L2 引用测量（缺）──▶ L3 信任（远）
                              │
                         Suite 工程回看（有，≠效果）
```

### A.2 距离总览

| 层 | 距离 | 已有 | 还缺 |
|----|------|------|------|
| **L1 被找到** | **近** | 页面诊断（schema/meta/content）、站点 SEO head、分发、AI 爬虫 PV | 官方号矩阵/SEO 常态（产品外）；实体一致性运营清单；勿把诊断「citation」当分引用率 |
| **L2 被引用** | **中（约半程）** | GEOFlow：KB/切片/Embedding/混合检索/证据元数据/受约束生成/审核；Suite handoff | **证明引用变好**；栏目事实卡标准；采编侧独立证据工作台；跨项目复用服务化 |
| **L3 被信任** | **远** | 通用图文 CMS/主题 | 创意多模态规范、模型可读结构、官媒背书产线与试点 |
| **L4 组织** | **远（非代码）** | 战略里有机制建议 | 试点责任制、培训选拔、例会与复盘流程 |

### A.3 L1：还差什么（轻）

**已对齐**：技术侧「可被发现」工具链基本齐（GEORank 诊断、GEOFlow SEO/分发/Analytics）。

**需补充（多数不在本仓研发）**：

- SEO 招聘与官方号 SOP（正文已写「正在做」）
- 栏目/实体命名一致性运营清单（轻量清单即可，非重产品）
- 汇报口径：诊断 citation / AI bot PV = **代理信号**，不是引用结果

### A.4 L2：还差什么（核心 · 数科主责）

**已有（不要低估）**——接近近程 L2 MVP 的**生产前半段**：

- 知识库 → 切片 → Embedding（可跑真实向量）→ 混合召回
- 证据元数据 + 任务绑定 KB + 生成要求引用证据
- 企业知识草稿、URL 导入、审核
- Suite：handoff / SSO / 发布回调 / 工程回看（薄集成可演示，待生产级验收）

**缺口按优先级**：

1. **测量闭环（最大缺口）**：可信仪表盘仅有产品草案；缺 Prompt 探针库、口径声明、重复采样与漂移、mention/citation taxonomy、前后对比、可审计导出。近程可用**手工周报抽样**顶上。
2. **栏目事实卡级知识工程产品形态**：现有「企业知识草稿 + KB」≠ 面向栏目的标准事实卡、覆盖率/向量化率看板、跨项目复用 API。
3. **对内证据召回工作台**：召回主要挂在任务管道；缺采编/审核侧独立「查证据」产品面。
4. **对外「答案素材出口」**：有分发与结构化页；缺面向答案引擎的事实摘要/权威素材包。
5. **Suite 从演示到生产**：Token/live handoff 联调验收；「回看」升级为含测量的效果复盘（依赖第 1 点）。

**L2 诚实进度**：生产底座约 60～70%；「证明被引用」约 0～10%；整体相对 L2 愿景约一半。

### A.5 L3 / L4：还差什么（中长期）

- **L3**：无创意型图文/音视频「人共鸣 + 模型可读」规范与产线；近期只规划试点样板，不进主研发排期。
- **L4**：培训、选拔、知识库责任制、引用复盘例会——组织动作，不写进代码里程碑。

### A.6 建议补齐顺序（汇报可用）

| 顺序 | 动作 | 为何 |
|------|------|------|
| 1 | 选 1～2 个试点栏目，用现有 Flow 跑通「资料→KB→受约束文章」 | 兑现 L2 生产半程，成本最低 |
| 2 | 定义栏目事实卡字段 + 覆盖率/向量化率看板 | 把「知识工程」从工具变成资产 |
| 3 | 手工答案抽样周报 → 再立项可信仪表盘 MVP | 先能「说话」，再产品化测量 |
| 4 | Suite 联调验收（live handoff + 回调 + 回看） | 演示变可交付集成 |
| 5 | L1 运营并行；L3 只做 1 条样板规范 | 不阻塞 L2 |
