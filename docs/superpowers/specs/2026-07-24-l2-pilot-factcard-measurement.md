# L2 试点工程计划：栏目事实卡 + 手工测量 SOP

> **状态**：可执行草案（待选定试点栏目后开工）  
> **日期**：2026-07-24  
> **归属**：战略近程 L2 兑现；承接 [差距评估附录 A](./2026-07-24-guangdian-ai-content-engineering-strategy.md#附录-a现状差距评估2026-07-24)  
> **测量产品愿景**：[可信仪表盘](./2026-07-22-geo-trust-dashboard-product.md)（本计划先手工，不替代产品化）  
> **非范围**：本阶段不接入 ChatGPT/Perplexity 等自动化爬取；不改诊断「citation」命名语义

---

## 0. 目标与成功标准

### 产品目标

在 **1～2 个试点栏目**上跑通：

1. 栏目资料沉淀为**标准事实卡**并入库（GEOFlow 知识库）  
2. 用事实卡/KB **约束生成**可发布内容  
3. 用**手工答案抽样周报**证明「是否被提及/引用」有可审计口径  

### 验收（DoD）

| ID | 验收项 | 通过标准 |
|----|--------|----------|
| P1 | 事实卡齐全 | 试点栏目 ≥1 套完整事实卡（见 §2 字段），已导入 KB 并完成切片 |
| P2 | 向量化 | 试点 KB 切片向量化率 ≥ 95%（或全量失败原因可解释） |
| P3 | 受约束生产 | ≥3 篇任务产物带证据引用标记（如 `[K1]`），经人工审核 |
| P4 | 发布闭环 | ≥1 篇完成发布；Suite 回看可见 handoff/回调事件（若 Token 已配） |
| P5 | 手工测量 | 连续 ≥2 周完成答案抽样表（§4），含 mention/citation 分类与原始答案存档 |
| P6 | 复盘纪要 | 1 份试点复盘：覆盖率、带证据比例、抽样结论、下一步是否立项仪表盘 |

## 1. 试点范围

| 项 | 约定 |
|----|------|
| 栏目数量 | 先 1 个，验证后再扩到 2 |
| 语料来源 | 栏目已有通稿、官网介绍、FAQ、权威报道摘要（须可溯源） |
| 生产系统 | GEOFlow 知识库 + 任务生产；GEORank Suite 负责移交/回看 |
| 周期 | 建议 4～6 周：建库 1 周 → 生产 2 周 → 抽样 2 周+ → 复盘 |

**开工前必须拍板**：试点栏目名称、责任人（内容审核 + 数科对接）、对外是否允许使用栏目真实实体名做抽样。

## 2. 栏目事实卡标准（字段）

每张事实卡对应「一个可被引用的权威陈述单元」。建议存为 GEOFlow 知识条目或 Markdown 后导入 KB。

### 2.1 必填字段

| 字段 | 说明 | 示例 |
|------|------|------|
| `entity_name` | 规范实体名（栏目/机构/产品统一写法） | 「某某栏目」 |
| `fact_id` | 稳定 ID | `col-xxx-f-001` |
| `claim` | 一句话事实陈述（可被引用） | 「该栏目于 YYYY 年开播」 |
| `evidence_source` | 来源标题/URL/内部文档号 | 官网 About 页 |
| `evidence_excerpt` | 原文摘录（≤300 字） | … |
| `effective_date` | 生效日 | 2026-01-01 |
| `review_status` | `draft` / `approved` / `rejected` | `approved` |
| `risk_level` | `low` / `medium` / `high` | `low` |
| `allowed_use` | 允许用途：选题/对外稿/广告前链 | `对外稿` |
| `forbidden_phrasing` | 禁用表述（可选但推荐） | 勿写「全国第一」若无出处 |

### 2.2 推荐扩展字段

| 字段 | 说明 |
|------|------|
| `aliases` | 别名、简称、易错写法 |
| `business_line` | 业务线/频道 |
| `related_entities` | 关联人物、节目、机构 |
| `faq_question` | 若本卡回答某 FAQ，写标准问法 |
| `expiry_date` | 过期日（时效事实必填） |

### 2.3 最低覆盖清单（试点栏目）

开工时按清单勾选，缺项优先补卡：

1. 栏目一句话定位  
2. 开播/所属机构/官方主页  
3. 核心栏目形态（时长、更新频率）  
4. 代表性成就或奖项（**仅有出处者**）  
5. 3～5 条高频 FAQ  
6. 官方账号/入口列表（服务 L1 实体一致性）  
7. 明确「不能说」的边界（禁用表述）

### 2.4 工程看板指标（人工或表格即可）

| 指标 | 计算 |
|------|------|
| 事实卡覆盖率 | 已 `approved` 卡数 / 最低覆盖清单项数 |
| 切片数 | KB chunk 总数 |
| 向量化率 | 已 embedding 切片 / 总切片 |
| 带证据生产比例 | 带引用标记的已审核稿 / 同期总生产稿 |

近程可用表格（飞书/Excel）维护；后续再做成后台看板。

## 3. 执行步骤（与现有 GEO 对齐）

```text
资料收集 → 填事实卡 → 审核 → 导入 GEOFlow KB
    → 切片/Embedding → 任务绑定 KB → 受约束生成
    → 人工审核发布 → Suite 工程回看
    → 每周手工答案抽样 → 复盘
```

| 步骤 | 动作 | 系统/工具 |
|------|------|-----------|
| 1 | 收集语料与出处 | 业务提供 |
| 2 | 按 §2 填事实卡并审核 | 表格 → `approved` |
| 3 | 导入知识库（条目或 URL/文件导入） | GEOFlow KB |
| 4 | 确认切片与 Embedding 完成 | GEOFlow（向量化率见 §2.4） |
| 5 | 创建任务，绑定该 KB，生成并要求证据引用 | GEOFlow Worker |
| 6 | 审核、发布；必要时 Suite live handoff | GEOFlow + GEORank Suite |
| 7 | 每周执行 §4 抽样 SOP | 人工 + 存档目录 |
| 8 | 第 4～6 周末出复盘纪要 | 文档 |

**Suite 联调（并行，不阻塞建库）**：配置 Token 后验收 live handoff、发布回调、回看事件；无 Token 时允许 preview 演示，但 P4 记为「部分通过」并注明原因。

## 4. 手工答案抽样 SOP（周报）

在可信仪表盘产品化之前，用本 SOP 产生**可审计**的引用信号。

### 4.1 固定口径（每周表头必填）

| 口径项 | 要求 |
|--------|------|
| 日期与执行人 | 必填 |
| 地区 | 如：中国大陆 |
| 语言 | 中文 |
| 客户端 | 网页 / App / 其它（写明） |
| 登录态 | 登录 / 未登录 |
| 模型或产品 | 如：某 AI 搜索 / Chat 产品名称与版本（能写则写） |
| Prompt 版本 | 使用下方探针库版本号，如 `probe-v1` |

### 4.2 探针题库 `probe-v1`（可增补，不可静默改旧题）

每题每周至少采样 **2 次**（间隔 ≥4 小时），记录漂移。

| ID | 探针（示例，上线前替换为试点栏目真实问法） |
|----|--------------------------------------------|
| Q1 | 「{实体名}是什么？主要做什么内容？」 |
| Q2 | 「介绍一下{实体名}的官方背景与所属机构」 |
| Q3 | 「{实体名}最近有哪些代表性节目或报道？」 |
| Q4 | 「和{竞品或相近栏目}相比，{实体名}有什么特点？」 |
| Q5 | 「哪里可以找到{实体名}的官方入口？」 |

> 将 `{实体名}` 换为试点规范名；竞品名需业务确认可对内使用。

### 4.3 标注 taxonomy（先分类，后计数）

对每次答案样本标注（可多选，但主标签唯一）：

| 标签 | 定义 |
|------|------|
| `mention` | 答案中出现实体名或明确指代，但无来源链接/出处 |
| `citation` | 出现可点击或可核对的来源，且来源指向我方权威域/官方页 |
| `recommendation` | 明确推荐关注/收看/访问我方 |
| `co_mention` | 与竞品同时出现 |
| `absent` | 未提及我方 |
| `error` | 提及但我方事实错误（单独记错误点） |

**禁止**：把 GEORank 诊断 citation 分或 AI 爬虫 PV 填进本表当作 citation。

### 4.4 周报表格模板（列）

`date | operator | product | locale | device | login | prompt_id | sample_n | raw_answer_path | primary_label | notes | drift_vs_prev`

- `raw_answer_path`：原始答案全文或截图路径（建议 `runtime/pilot-samples/YYYY-Wxx/`，**勿提交密钥**；若含敏感内容则仅内网盘）  
- `drift_vs_prev`：与同题上次样本相比是否明显变化（是/否 + 一句话）

### 4.5 周报结论模板（四行）

1. 本周 `mention` / `citation` / `absent` 次数  
2. 是否出现事实错误（`error`）及是否已回写事实卡  
3. 与上周相比的方向（升/平/降 + 不确定因素：漂移、产品改版）  
4. 对生产侧的一条动作建议（补哪张卡 / 哪篇稿）

## 5. 角色与节奏

| 角色 | 职责 |
|------|------|
| 数科 | KB/Embedding/任务管线、Suite 联调、抽样表工具与存档规范 |
| 内容审核 | 事实卡 `approved`、稿件审核、禁用表述 |
| 运营/SEO | L1 官方入口一致性；不阻塞 L2 |
| 试点负责人 | 周报复盘会（15～30 分钟） |

建议例会：**每周固定 1 次**，只看 §2.4 指标 + §4.5 四行结论。

---

## 6. 退出与升级条件

| 条件 | 动作 |
|------|------|
| P1–P6 全部通过 | 复盘后决定是否扩第二个栏目 |
| 连续 4 周手工抽样可稳定产出 | 立项可信仪表盘 MVP（产品文档已有） |
| 事实错误反复出现 | 暂停扩栏目，先补审核与禁用表述 |
| Suite Token 长期无法配置 | 生产闭环仍算通过；集成项单独开缺陷单 |
