## 1. 目标与边界

### 目标（人话）

编辑打开工作台，能看见进行中的选题；点「下一步」就落到该做的那一页。  
查页面做完可一键开出新选题。  
写稿只在选题工作台；**拓词问法未确认前不能写稿**。  
知识库只做知识（文章 / 切片 / 证据），不做写稿。

### 本轮做

| # | 能力 | 落点 |
|---|------|------|
| 1 | 进行中选题（最多 3 条）+ 一步跳转 | `/suite` |
| 2 | 旧「五步进度」收成次要/折叠 | `/suite` |
| 3 | 查页面「用于新建选题」直接建草稿并打开定策 | `/diagnostic` → `/strategies` |
| 4 | 「下一步」统一判断顺序 + 深链参数 | 服务端摘要字段 + 各页承接 |
| 5 | 拓词问法确认后才能写稿（硬卡） | 选题写稿页 + 挂任务/生成接口 |
| 6 | 拓词结果写回当前选题（最小闭环） | `/keywords`（或定策页等价确认） |
| 7 | 知识库仅保证「去备知识」入口清楚 | `/knowledge?strategy=` 情境条 |

### 本轮不做

- 知识库写稿 / 送审 / 过审  
- 知识库文章·切片·证据管理大改  
- 分发代发、阅读量看板、装饰监控  
- 真白号自动采样  
- 登录页品牌、Mobile 底栏新建（可另轮）

## 2. 与现网闸门的对齐（必须先拍板）

### 矛盾

Grill 顺序是：

**诊断 → 初次摸底 → 定策过审 → 拓词写回 → 备知识 → 写稿 → …**

现网则是：

- 登记摸底前就要 ≥3 条问法  
- **送审/批准**还要求：≥3 问法 + 知识文档可检索  

若批准仍卡「知识 + 问法终稿」，则「过审后再拓词 / 再备知识」在系统里走不通。

### 本轮采用的闸门拆分（建议已写入本方案，开工即按此改）

| 环节 | 仍要满足 | 不再作为批准前置 |
|------|----------|------------------|
| 送审 / 批准为可执行 | 平台、问题类、内容取向、渠道要点、成功信号；**已挂诊断**；**已登记摸底**；写≠审等角色规则 | **知识文档可检索**；**拓词已确认** |
| 登记摸底 | 至少 3 条**问法草案**（可在定策页填写，供白号提问） | — |
| 拓词完成 | 人确认选用问法并写回策略，且 ≥3 句；打标 `meta.query_pack_confirmed=true` | — |
| 备知识就绪 | 已绑知识库/文档且可检索（或标签包齐，与现 `handoff_checklist.knowledge` 一致） | — |
| 写稿（挂任务 / 生成 / 写稿主按钮） | 策略已可执行；**拓词已确认**；**知识已就绪** | — |

含义（给编辑看的说法）：

1. 定策阶段可以先写「摸底用的三句问法草案」。  
2. 审核通过的是「这条选题可以开工」，不是「问法和素材已经终稿」。  
3. 过审后去做拓词确认、备知识；两样齐了才能写稿。

> 冒烟脚本若仍按「批准前必须绑齐知识」编写，本轮需同步改断言，避免假失败。

## 3. 「下一步」判断顺序（只亮一个）

按从上到下，命中第一条未完成项：

| 序 | 条件未满足时 | 按钮文案（示例） | 跳转 |
|----|--------------|------------------|------|
| 1 | 无诊断报告 | 去挂查页面结果 | `/strategies?strategy={id}&tab=craft`（定策里挂诊断）；无报告可辅链 `/diagnostic` |
| 2 | 无摸底快照 | 去做投放前摸底 | `/observe?strategy={id}&phase=baseline` 或定策内摸底入口 |
| 3 | 状态为草稿/待审，或定策字段不齐 | 去补全并送审 / 去批准 | `/strategies?strategy={id}&tab=craft` |
| 4 | 可执行但拓词未确认 | 去确认观测问法 | `/keywords?strategy={id}`（写回后返回选题） |
| 5 | 拓词已确认但知识未就绪 | 去备知识 | `/knowledge?strategy={id}` |
| 6 | 知识就绪但稿件未齐/未过审 | 去写稿 | `/strategies?strategy={id}&tab=write` |
| 7 | 稿件齐但未登记双链投放 | 去登记发布 | `/strategies?strategy={id}&tab=publish&pipe=register` |
| 8 | 已投放但无复测 | 去做投放后复测 | `/strategies?strategy={id}&tab=publish&pipe=after` 或 `/observe?...&phase=after` |
| 9 | 有复测未判定/未留档 | 去看效果与留档 | `/strategies?strategy={id}&tab=publish&pipe=after` |
| — | 全部完成 | 查看本条选题 | `/strategies?strategy={id}&tab=overview` |

### 服务端字段（建议）

在策略序列化中增加（名称可微调，前后端共用同一套）：

```text
next_action: {
  key: "diagnostic" | "baseline" | "craft" | "expand" | "knowledge" | "write" | "deploy" | "after" | "verdict" | "done",
  label: "去确认观测问法",          # 人话按钮
  href: "/keywords?strategy=...", # 可直接跳
  tab: "craft" | "write" | ...,     # 选题页时用
  pipe: "register" | "after" | null
}
```

工作台与选题总览**都读这一字段**，避免两套逻辑。

## 4. 分页面怎么改

### 4.1 工作台 `/suite`

- **主区**：新增「进行中选题」卡片列表（最多 3 条）。  
  - 数据：`GET /api/geo-strategies?limit=50`，前端过滤进行中状态后取前 3；或后端加 `active_only`（可选）。  
  - 进行中：`draft | pending_review | executable | deployed | observing`（已判定生效/部分/无效的不进主列表，或单独「最近完成」弱化展示——本轮可不做）。  
  - 每卡：标题、平台、一句状态（可用现有进度文案）、主按钮 = `next_action.label` → `next_action.href`。  
  - 「查看全部」→ `/strategies`。  
- **空态**：无进行中时，主按钮「去查页面」→ `/diagnostic`，次按钮「新建选题」→ `/strategies?tab=craft`。  
- **旧五步**：折叠为「了解作业顺序」次要区块（默认收起），不再占主视觉；演示看板弱化或置于折叠下方。  
- 顶栏主 CTA：若有进行中，改为第一条的下一步；否则「去查页面」。

### 4.2 查页面 `/diagnostic`

- 报告**成功完成**（非示例报告）时，主按钮文案：**用于新建选题**。  
- 点击行为：  
  1. `POST /api/geo-strategies/seed`（或专用 `from-diagnostic`）  
     - `platform`：默认 `doubao`（可在弹层三选一，本轮允许极简默认 + 定策页可改）  
     - `question_class`：由页面 URL/标题生成短句，缺省「页面认知 · {host}」  
     - `gap_note`：取报告缺口摘要前若干字  
     - 创建后立刻 `attach-diagnostic`  
  2. 跳转 `/strategies?strategy={id}&tab=craft`  
- 失败/未完成：不展示该主按钮，或禁用并说明原因。  
- 示例报告：不可一键建题。

### 4.3 选题工作台 `/strategies`

- 承接 `?strategy=&tab=&pipe=`（现已有部分，补齐 pipe）。  
- **写稿 Tab**：若 `query_pack_confirmed` 不为真，展示阻断说明 +「去确认观测问法」；隐藏/禁用挂任务与生成。  
- **定策**：保留问法草案编辑（供摸底）；文案区分「摸底草案」与「拓词确认后的观测问法」。  
- 总览卡「下一步」与工作台同一 `next_action`。

### 4.4 拓词 `/keywords`

- 支持 `?strategy=`：顶条显示当前选题。  
- 最小闭环：勾选或确认 ≥3 句 →「写入当前选题」→ `PATCH/POST` 更新 `query_variants`，并设 `meta.query_pack_confirmed=true`。  
- 成功后提供「回到写稿」→ `/strategies?strategy=&tab=write`（若知识未齐则按 next_action 去备知识）。

### 4.5 知识库 `/knowledge`

- **不**增加写稿任务 Tab。  
- 保留/理顺 `?strategy=` 情境条：说明「正在为某选题备素材」+ 返回选题按钮。  
- 文案避免「在此写稿」。

## 5. 接口与脚本改动清单

| 项 | 说明 |
|----|------|
| `serialize_strategy` / `next_action` | 按 §3 计算 |

## 6. 验收（人话路径）

1. 库中有进行中选题时，打开工作台能看到最多 3 条，点下一步到达正确页签。  
2. 查页面跑完真实报告，点「用于新建选题」，进入定策且诊断已挂上。  
3. 策略可执行但未确认问法时，写稿页被挡住，引导去拓词。  
4. 拓词写入 ≥3 句并确认后，若知识已齐，可进入写稿并挂任务。  
5. 知识库打开带 `strategy=` 时，只表现为备素材，无写稿主流程。  
6. 旧五步不再抢工作台第一眼。

## 7. 建议施工顺序

1. 后端：`next_action` + 批准/写稿闸门拆分 + 问法确认字段  
2. 选题页：深链 + 写稿硬卡 + 总览按钮对齐  
3. 工作台：进行中列表 + 五步折叠  
4. 查页面：一键建题  
5. 拓词：写回最小闭环  
6. 知识库文案/情境条收束  
7. 改冒烟脚本并跑通
