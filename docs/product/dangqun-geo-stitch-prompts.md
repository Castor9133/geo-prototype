# 党建党媒 GEO 全站 · Stitch 设计提示词包

> 用法：先跑「全站总设」→「页面逻辑」→「反馈/失败态组件」→「状态机」，再按模块逐屏（含失败帧）。  
> 目标：一套视觉语言覆盖**所有编辑日常页**；Stitch 必须懂**九步主链、闸门、岗位差异**，不能只画快乐路径。  
> 用户：广电/党媒普通编辑（编写/审核）；技术支持另有后台，风格同源但信息密度更高。  
> 产出：设计系统 + 逻辑图 + 多状态/失败态 + Desktop 关键页；Mobile 出壳与 2 个核心页即可。

---

## 现状说明（给设计，勿写进界面）

当前实现存在**两套气质**，请统一成一套：

| 区域 | 现状问题 |
|------|----------|
| 全站壳 `inner-shell` | 暖奶油底 + 亮蓝主色 + 橙色强调，偏「通用 SaaS / 仪表盘」 |
| 选题策略页 | 冷灰蓝底 + 墨蓝/青绿，更克制，但与全站割裂 |
| 文案 | 多页仍有工程词（Suite、baseline、ID、ready 等） |

**Stitch 任务 = 统一视觉 + 统一白话文案骨架**，后续我们按图回落全站 CSS/页面。

## 0. 全站总设（必须先贴）

```text
请为「党建党媒 GEO 工作台」做全站 UI/UE 设计系统与高保真关键页（中文）。

【产品一句话】
帮助党媒/广电编辑：先查清页面与问答平台现状 → 定选题策略 → 用审过的素材写稿 → 发到官网和媒体号 → 再测 AI 有没有答到我们 → 见效则留档。
验收看「选题策略有没有见效」，不是看发文篇数。

【用户与岗位】
- 编写：查页面、摸底/复测、起草策略、写稿、登记发布
- 审核：批准策略、过审稿件、确认效果与留档
- 技术支持：账号/白号/排障（后台），不替代日常业务审批
界面禁止工程师术语：UUID、API、baseline、after、六元组、LLM、L2、ready、smoke、geo_run、Suite（导航可改为「工作台」）

【全站信息架构（顶栏导航，从左到右）】
1. 工作台（原 GEO Suite：总览/五步引导）
2. 查页面（诊断）
3. 知识库（备素材、写稿、过审）
4. 选题策略（主作业：一条问题×一个平台）
5. 拓词（围绕问题扩问法/选题线索）
6. 分发预览（渠道稿预览，不代发）
7. 观测（投放前摸底 / 投放后复测提问）
8. 配置（个人与站点偏好；勿做成研发控制台脸）

【全站布局骨架（每页必须同源）】
- 顶栏：Logo/产品名「党建党媒工作台」+ 主导航 + 账号/岗位
- 页头区：衬线大标题 + 一句业务说明（≤2 行）+ 可选本页步骤条
- 主内容：单列或「主列+窄侧栏」，不要仪表盘数字墙占首屏
- 反馈：顶部/页内轻提示条（成功绿/警告琥珀/失败红），文案人话
- 页脚：极简，不抢内容

【视觉方向——全站统一（重要）】
气质：可信的传媒编辑部作业系统；纸质文档感 + 现代工作台；干净、可读、稳重。
- 背景：浅暖灰纸色即可，但不要做成「奶油底+赤陶大衬线杂志封面」网红套路；可轻微纸纹/柔和分区，忌紫粉渐变与霓虹
- 主色：墨蓝（约 #1F4B7A）用于主按钮、当前导航、关键强调
- 辅色：青绿（约 #2A6F6A）用于「推进/生成/通过」类积极动作
- 强调色：琥珀仅用于警告；砖红仅用于失败/未生效；成功用沉稳绿
- 卡片：白纸面、细线分隔、轻阴影；圆角中等；禁止多层大阴影与玻璃拟态堆叠
- 字体：标题 Noto Serif SC；正文 Noto Sans SC；字阶全站统一
- 组件：按钮（主/次/危险）、状态徽章、步骤条、表格、表单、空状态、抽屉/面板——一次定义，各页复用
- 动效：导航当前态、步骤切换、保存成功——全站同一套，克制

【硬性禁止】
紫/Indigo 科技风；奶油底+赤陶杂志风；报纸细线密栏；深色赛博发光；emoji 装饰；首屏 KPI 墙；英文状态词。

【UE 总原则】
- 每页回答一个问题：「我现在该干什么？」
- 主按钮每视图 ≤1 个；次要收进「更多」或次按钮
- 编写/审核主按钮可不同，但布局骨架相同
- 技术编号默认折叠在「需要时再填」
- Desktop 1440；Mobile 390 先做壳+工作台+选题策略

请先输出：
A) 色板/字阶/间距/组件规范（Design Tokens）
B) 顶栏+页头+页脚标准壳（含导航中文标签）
C) 全站「反馈组件族」：空状态 / 加载中 / 成功 / 警告 / 被拦住 / 失败（样式见后文「逻辑与失败态」）
D) 再按我后续提示出各业务页与失败帧
```

## 0.1 页面逻辑总图（紧接总设粘贴）

```text
请先消化下面的「页面逻辑」，再画任何业务页。界面文案用白话；括号里的编号只给你对齐产品，不要印在 UI 上。

【主链九步（一条选题策略的一生）】
① 查页面问题（诊断官网/栏目页缺口）
② 投放前摸底（白号在目标问答平台按问法提问，登记现状）
③ 定选题策略（编写起草 → 审核批准；缺①或②不能批成「可以写稿」）
④ 备好素材（知识库绑定可用素材）
⑤ 写稿过审（至少 2 篇：栏目说明类 + 常见问答类；连续过审）
⑥ 登记已对外发布（官网链接 + 任一媒体号链接；系统不代发）
⑦ 投放后复测（同一问题、同一平台，白号再测）
⑧ 看效果（审核确认：已见效 / 部分见效 / 还没见效；可对照摸底→复测变化）
⑨ 改策略开新版本，或见效内容留档入库（留档需审核确认；强制留档另走技术终确）

【环间闸门（被拦住时必须有 UI，不能静默灰掉）】
- 没有查页面结果 → 不能把策略批成「已批准可以写稿」
- 没有投放前摸底样本 → 同上
- 策略未批准 → 不能正式领题写稿（可提示先送审/等批准）
- 素材未备齐 / 不可检索 → 出稿按钮被拦，说明缺什么
- 稿件未全部过审（<2 篇或有未过审）→ 不能登记为「已对外发布」完成态
- 未登记双链接 → 不能开始「投放后复测」
- 复测样本不齐 → 不能做正式效果判定
- 已判定的旧策略 → 只读；要改必须「开新版本」
- 编写不能自己批准自己起草的策略；审核主责批准/判定；技术支持不替代日常审批

【页面怎么串】
工作台：总览「卡在哪一步」→ 一键跳到对应页
查页面 → 结果「用于新建选题策略」→ 选题策略
观测（摸底）→ 写回选题策略 → 才能送审/批准
选题策略（已批准）→ 知识库写稿 → 分发预览（可选）→ 人去官网/媒体号发布
选题策略「登记已发布」→ 观测（复测）→ 写回 → 选题策略「确认效果」→ 留档或开新版本
拓词：给选题策略提供问法线索，不是发稿

【每页只回答一个问题】
- 工作台：今天从哪条策略继续？
- 查页面：这个网址缺什么？
- 知识库：素材齐了吗？稿过审了吗？
- 选题策略：这一条下一步点哪个按钮？
- 拓词：还能怎么问？
- 分发预览：发出去长什么样？（不代发）
- 观测：这轮提问结果怎么登记回去？
- 配置：我的账号与偏好

请输出一张「九步流程图 + 闸门说明」示意图（中文），并列出全站 6 种反馈组件草图。
```

## 0.2 全站反馈与失败态样式（必须出组件帧）

```text
基于全站色板，请画出「反馈组件族」一页（Desktop），六种缺一不可。之后所有业务页的成功/失败都复用这一套，禁止每页自创一套红条。

【1. 空状态 Empty】
- 居中插画或简线图标（克制）+ 标题 + 一句说明 + 1 个主按钮
- 例：「还没有选题策略」→「创建第一条」
- 背景仍是纸色工作区，不要大面积灰蒙层

【2. 加载中 Loading】
- 列表用骨架屏（卡片轮廓闪烁），按钮旁可用细 spinner
- 长任务（查页面、出稿、观测写回）：页内进度条或步骤「正在检查…预计 1–2 分钟」
- 禁止全屏堵死无法返回；允许「取消/回列表」次按钮

【3. 成功 Success】
- 顶部轻绿提示条，或按钮旁短暂「已保存」
- 文案人话：「策略已送审，请换审核同事批准」
- 不弹庆祝模态抢焦点（除非留档完成等里程碑，可用轻确认框）

【4. 警告 Warning（可继续但不完整）】
- 琥珀左边条 + 图标 + 标题 + 说明 + 可选「仍要继续」次按钮
- 例：摸底样本只有 2 条问法（建议 ≥3）；白号不够不能算正式验收；部分问法无法解析引用位次

【5. 被拦住 Blocked / 闸门（逻辑不允许下一步）】
- 不是大红报错；用「墨蓝信息面板」或琥珀面板
- 结构：标题「还不能做这件事」+ 缺什么清单（可勾视已齐/未齐）+ 主按钮跳去补齐页
- 例：「还不能批准可以写稿」→ 缺：查页面结果、投放前摸底
- 主按钮禁用时，旁边必须有「为什么不行」展开，禁止只有灰按钮无解释

【6. 失败 Error（操作未成功）】
- 砖红左边条或页内错误卡；可关闭
- 结构：发生了什么（人话）+ 可能原因（1–3 条）+ 主按钮「重试」+ 次按钮「联系技术支持」
- 禁止堆栈/报错码刷屏；技术编号折叠在「详情」
- 表单校验：字段下红字，提交时焦点滚到第一个错误

【权限/岗位不对】
- 整卡替换主按钮区：「当前是编写岗位，批准需切换审核账号」+「退出并换人登录」
- 不要假装按钮可点然后报错

【网络/登录失效】
- 顶部固定条：「登录已过期，请重新登录」主按钮去登录页；底下内容可半透明但勿假可编辑

请输出：上述 6+2 种组件的视觉规范（色、圆角、图标、文案示例各 1）。
```

## 0.3 选题策略状态机（主战场逻辑）

```text
请按状态机设计「选题策略作业卡」——同一张卡骨架，不同状态只换：徽章、检查表勾选、主按钮、是否只读。

【状态 → 界面表现 → 主按钮（编写 / 审核）】

1) 草稿
- 徽章灰「草稿」
- 检查表：查页面/摸底多半未齐
- 编写主按钮：填写策略内容 → 送审策略
- 审核：无批准按钮；可只读查看

2) 等审核
- 徽章琥珀「等审核」
- 编写：主按钮变为「撤回修改」（次）或等待说明；不能自批
- 审核主按钮：批准可以写稿（若闸门未齐则点开「被拦住」面板）

3) 已批准可以写稿
- 徽章青绿「已批准可以写稿」
- 编写主按钮：去知识库写稿（或页内「写栏目说明并出稿 / 写常见问答并出稿」）
- 审核：可看进度；主路径转到过审稿件

4) 写稿/过审中（可作子状态，徽章「写稿过审中」）
- 显示 2 篇进度：未齐/审核中/已过审
- 编写：送审某篇；审核：过审
- 未齐时「登记已对外发布」禁用 + 闸门说明

5) 已登记发布
- 徽章蓝「已登记发布」
- 展示官网链接、媒体号链接（只读摘要）
- 编写主按钮：开始投放后复测

6) 正在复测
- 徽章琥珀「正在复测」
- 主按钮：去观测登记结果 / 刷新复测进度
- 样本不齐时不能进判定

7) 已见效
- 徽章绿「已见效」
- 审核主按钮：见效内容留档入库
- 编写：可查看；开新版本为次按钮

8) 部分见效
- 徽章琥珀「部分见效」
- 主按钮：开新版本改策略（编写起草）或审核确认后同样引导迭代
- 说明：哪些问法够、哪些不够（对照摸底）

9) 还没见效
- 徽章红灰「还没见效」
- 主按钮：开新版本；旧版只读
- 失败归因区：建议改问法/补素材/换渠道（白话）

10) 已留档（终态之一）
- 徽章绿「已留档」
- 整卡只读；次按钮「查看留档素材」

【作业卡上的迷你检查表（八格，白话）】
查页面 / 投放前摸底 / 策略已批准 / 素材已备 / 稿件已过审 / 已双渠道发布 / 投放后复测 / 效果已判定
齐=绿勾；缺=灰圈；当前步=墨蓝点。点击未齐项可跳转补齐页。

【必须另出的失败/异常帧（选题策略）】
A. 点「批准」但缺摸底 → 被拦住面板
B. 送审时表单缺问法(<3) → 字段错误
C. 出稿失败（模型超时）→ Error 卡 + 重试
D. 登记发布只填了官网没填媒体号 → 字段错误
E. 白号不足提示条（警告，非正式验收）
F. 已判定策略误点编辑 → 只读遮罩 +「开新版本」
G. 编写账号看到批准按钮位置 → 换成「需审核同事操作」说明（权限态）
```

## 2. 工作台（原 Suite 总览）

```text
设计「工作台」首页 Desktop。这是编辑登录后的总入口，不是数据大屏。

【本页一句话】
看清本周选题推进到哪，并一键进入下一步。

【模块】
1. 欢迎条：岗位 + 「今天建议从选题策略继续」主按钮
```

## 3. 查页面（诊断）

```text
设计「查页面」Desktop。

【用户任务】
输入官网/栏目页地址，看清「页面有哪些不利于被 AI 引用的问题」，拿到可挂到选题策略上的诊断结果。

【结构】
- 页头：查页面 + 说明「先找缺口，再决定写什么」
- 主操作区：网址输入 + 「开始检查」主按钮
- 结果区（示例已完成态）：
  - 总分/总体判断用白话（如「中等，建议先补常见问答」）
  - 缺口清单（可读句子，不要 JSON）
```

## 8. 观测（摸底 / 复测）

```text
设计「观测」Desktop。

【用户任务】
白号在豆包/元宝/DeepSeek 按问法提问；半自动登记摸底或投放后复测。

2. 进行中（步骤高亮）
```
