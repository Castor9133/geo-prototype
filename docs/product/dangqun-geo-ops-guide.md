# 党建党媒 GEO 平台 · 业务操作指南

> 给编辑部 / 技术部日常干活用。不讲原理，只讲「谁、何时、点哪里、交出什么」。  
> 产品名：**党建党媒 GEO 平台快速落地方案**  
> 作业本体是**策略**，不是单篇文章。  
> **冻结版**：2026-08-04 · 与 PRD `2026-08-04-freeze` 对齐（①–⑨ + 白号池 + 强制三闸）

---

## 0. 开干前准备（一次性）

| 事项 | 谁负责 | 完成标准 |
|------|--------|----------|
| 账号与岗位 | 技术支持（admin） | 每人有账号；岗位标成 **编写（editor）** 或 **审核（reviewer）** |
| 白号池 | 技术备号，编辑操作 | 豆包 / 元宝 / DeepSeek **每平台 ≥5 个白号**就绪 |
| 知识素材入口 | 双方约定 | 外采打标入库 **或** 本仓录入，同一道门禁 |
| 渠道底线 | 编辑部确认 | 第一现场官网可发；至少一个媒体号可发（公号/头条/抖音/百科/百家号等） |

登录后常用入口：

| 入口 | 干什么 |
|------|--------|
| **策略**（`/strategies`） | 定策、审批、登记投放、判定、沉淀——**主战场** |
| **诊断** | 查目标页缺口，出诊断报告 |
| **知识库** | 备料、选提示词、领题出稿、过审 |
| **观测 / Suite 观测步** | 白号摸底（baseline）与投放后复测（after） |

## 1. 一条策略怎么跑完（①–⑨）

按环做；**上一环没交齐，下一环不要硬过。**

### ① 诊断

1. 编写岗打开**诊断**，对目标页（优先第一现场相关页）跑诊断。  
2. 确认有可用的缺口清单（报告状态完成）。  
3. 记下报告 ID；后续在策略上「挂接诊断」。

**本环出口**：一份可挂接的诊断报告。

---

### ② 初次观测（baseline）— 定策前摸底

1. 明确：**哪个平台**（豆包 / 元宝 / DeepSeek 选一）、**哪类问题**（如「第一现场是什么栏目」）、至少 **3 条问法**。  
2. 用**白号**在该平台按问法提问并回传样本（正式验收必须白号；固定查询号只作点名辅助，不算数）。  
3. 在策略侧登记 baseline（可先占位再补齐样本；**正式闭环样本须齐**）。

**本环出口**：该平台 × ≥3 问法的摸底结果——现在有没有被提到、引用排到哪、有没有我们自己的站。

---

### ③ 定策略

1. 编写岗在**策略看板**生成草稿种子：平台 + 问题类 + 缺口说明。  
2. 点「编辑六元组」补齐并保存：  
   - 目标平台（一策一台）  
   - 问题类 + ≥3 条观测问法  
   - 内容供给取向（如：1 深文 + 1 FAQ）  
   - 渠道矩阵（官网必含 + 媒体号类型）  
   - 成功信号（默认：提及且引用进前 10）  
   - 知识绑定：**文档列表 + 标签包** 两项都要  
   - Geo Run / 知识库按现场约定填好  
3. 挂接①诊断；登记②baseline。  
4. 编写岗「提交审批」→ **另一人**审核岗「审批可执行」（起草人不能审自己的）。

**本环出口**：状态变为可执行；看板检查表「诊断 / baseline / 可执行」为齐。

---

### ④ 备知识

1. 确认策略绑定的文档都已过门禁、能用于起草。  
2. 缺料则：外采入库或本仓录入 → 过审 → 再绑进策略。  
3. 标签包与问题类、栏目/站点一致（如 `site_id`、主题/八爪）。

**本环出口**：策略上「文档集 ∧ 标签包」齐全。

---

### ⑤ 执行供给（出稿，不是验收本体）

1. 策略「挂深文任务」「挂 FAQ 任务」（至少 2 篇，种类按取向来）。  
2. 在知识库/内容引擎：选题 → 选提示词 → 出模板稿 → 出渠道适配稿 → **提交审核**。  
3. 审核岗连续过审至全部 **ready**（建议两人分写/审）。  
4. 预览渠道稿，按矩阵准备真发。

**本环出口**：该策略下 ≥2 篇且全部过审；检查表「执行物全过审」为齐。

---

### ⑥ 已投放（系统不代发）

1. 人把内容发到：**第一现场官网** + **任一媒体号**。  
2. 回到策略看板「登记已投放」：官网 URL、媒体号类型、媒体号 URL。

**本环出口**：双 URL + 投放时间落库；状态为已投放。

---

### ⑦ 复测观测（after）

1. 用**同一平台、同一批问题类问法**，白号再问一轮。  
2. 系统建 after 快照并回传样本（折叠引用要展开后再看位次）。  
3. 正式口径：无引用列表的问法，最高只能算「部分」。

**本环出口**：after 样本齐，可进入判定。

---

### ⑧ 策略判定

1. 系统给出建议（多数决：≥2/3 问法生效 → 策略生效；1/3 → 部分；0 → 未生效）。  
2. **审核岗确认判定**（可看 baseline→after 变化，不凭感觉改口径）。  
3. 生效 → 可建议沉淀；未生效/部分 → 准备开新版本，不要原地改已判定策略。

**本环出口**：策略带正式判定结果。

---

### ⑨ 迭代或沉淀

| 结果 | 动作 |
|------|------|
| 生效 | 审核岗确认沉淀进故事/证据层（L2）；禁止无人自动入库 |
| 未达标 | 「开新版本」→ 回到补知识/改供给/改问法，再走审批 |
| 业务坚持入库但未达标 | **强制沉淀三闸**：审核发起 → 另一业务确认 → **技术支持终确**（写清理由） |

## 2. 岗位分工（避免扯皮）

| 事 | 编写 | 审核 | 技术支持 |
|----|------|------|----------|
| 诊断、摸底观测、起草策略、出稿、白号操作 | ● | 可协助 | 备号/排障 |
| 策略审批、稿件过审、判定确认、L2 确认 | | ● | |
| 强制沉淀终确、账号岗位、门禁与白号池 | | 发起/业务确认 | ● 终确 |
| 日常替业务批策略 | | | **不做** |

原则：**谁起草谁不能自审；谁拍板谁对判定负责。**

---

## 3. 渠道与观测硬规矩（操作时别破）

- 投放最低：**官网 + 一个媒体号**，系统只登记，不代发。  
- 观测平台：豆包 / 元宝 / DeepSeek；**一策略只盯一个平台**。  
- 正式摸底/复测：**白号**；号不够时不要假装验收过。  
- 成功默认：**被提到，且引用进前 10**；要加严可以，默认不要放宽成「只要提到」。  
- 验收一条策略，必须有 **摸底 + 复测**；只有复测没有摸底，不算过。

---

## 4. 2 个月怎么算做成

- 真人按上面 ①–⑨ **周循环**能自己跑。  
- 数量目标：**6 条策略** = 2 个问题类 × 3 个平台。  
- 每条都要交齐：诊断 → 摸底 → 可执行策略 → 知识 → ≥2 篇过审 → 双渠道已投 → 复测 → 判定 → 迭代或沉淀。

看板每条策略上的**环间检查表**（诊断 / baseline / 可执行 / 知识 / 执行物 / 已投放 / after / 判定）可直接当交接清单用。

---

## 5. 常见卡点（业务话）

| 现象 | 先查什么 |
|------|----------|
| 批不成「可执行」 | 诊断挂了没有；baseline 挂了没有；六元组（含文档+标签）齐不齐；是不是自己审自己 |
| 登不了已投放 | 是否已有 ≥2 篇且全部过审；官网/媒体号 URL 是否都填了 |
| 判定一直出不来 | after 样本有没有；问法是否与策略一致；引用列表是否展开 |
| 想入库但未生效 | 走强制三闸，或先开新版本改策再观测 |
| 白号不够 | 技术补号；在此之前不要把「探测号结果」写成验收 |

## 6. 周节奏建议（编辑部可直接套）

| 节奏 | 建议动作 |
|------|----------|
| 周一 | 选定本周问题类与平台；跑/挂诊断；排白号摸底 |
| 周二 | 定策略并审批；核对知识绑定 |
| 周三 | 出齐深文+FAQ，连续过审 |
| 周四 | 真发官网+媒体号并登记；启动复测 |
| 周五 | 判定；沉淀或开新版本；周报只报「策略条数与判定」，不报发文篇数当成绩 |
