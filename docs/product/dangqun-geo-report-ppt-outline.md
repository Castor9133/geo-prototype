# 党建党媒 GEO 平台 · 汇报 PPT 大纲

> 用途：对内汇报 / 立项与阶段成果汇报  
> 听众：已了解行业与 GEO 背景的领导；**不要科普「什么是大模型/GEO」**  
> 只讲四件事：**解决了什么问题、踩住了什么痛点、沉淀了什么、为什么要交给我们做**

建议时长：12–15 分钟 + 答疑；约 **12–14 页**。

---

## 封面

**标题**：党建党媒 GEO 平台快速落地方案 · 阶段汇报  
**副题**：以策略闭环，把「被 AI 采信」做成可验收的周工作  
**信息**：汇报单位 / 日期 / 汇报人  

口播一句：我们不是多做了一个发文工具，而是把「定策—供给—投放—复测—判定」收成一条可管的业务链。

## P1 · 今天要拍板的三件事

1. 确认：**验收看策略闭环，不看发文篇数**  
2. 确认：2 个月内跑通 **6 条策略**（2 问题类 × 三平台）为阶段目标  
3. 确认：编辑部主责判定与过审，技术部主责账号/白号/门禁与强制终确——**技术不替代日常业务审批**

（本页不展开细节，后面用事实支撑。）

## P2 · 业务上到底卡在哪（问题）

用业务语言，不用术语堆砌：

| 问题 | 表现 |
|------|------|
| **不知道 AI 侧现状** | 发了不少内容，说不清豆包/元宝/DeepSeek 里「我们有没有被提到、有没有被引到前面」 |
| **不知道先改什么** | 页面缺口、问法缺口、供给缺口搅在一起，定策靠感觉 |
| **做完无法验收** | 以篇数、排期当成绩；投放后没有「同一问题再测一遍」的对照 |
| **资产留不住** | 好稿、好口径、观测结论散落在群和文档里，下一轮从零开始 |
| **权责不清** | 谁拍板策略、谁审稿、谁能破例入库，容易「技术拍板业务」或无人收口 |

一句话：**不是缺一个写稿按钮，是缺一条「摸底→定策→供给→复测→沉淀」的责任制闭环。**

---

## P3 · 对应痛点（领导已熟悉的场景）

用 4 个痛点钉死，便于共鸣：

1. **「发了但进不了答案」**——供给与观测脱节  
2. **「测了但说不清进步」**——只有复测、没有摸底对照  
3. **「审了但资产不增值」**——过审稿进不了可复用证据层  
4. **「急了就破规矩」**——例外入库没有三道闸，事后无法审计  

每点配半句「我们怎么卡住」：见后页机制，本页只点痛。

---

## P4 · 我们交付的东西（解决了什么）

一张总图（口述即可，PPT 用流程条）：

**诊断 → 摸底观测 → 定策略 → 备知识 → 出稿过审 → 双渠道投放登记 → 复测 → 判定 → 迭代或沉淀**

解决了什么（对照 P2）：

| 原问题 | 现在怎么收口 |
|--------|----------------|
| 不知 AI 侧现状 | 定策前强制摸底；投放后再测同一问题类 |
| 不知先改什么 | 诊断缺口 + 摸底结果写入策略「缺口说明」，审批可见 |
| 无法验收 | 验收单位 = **一条策略是否生效**（提及且引用进前 10 的多数决） |
| 资产留不住 | 生效可沉淀证据层；强制入库走三闸可追溯 |
| 权责不清 | 编写 / 审核分岗；起草人不可自审；技术不审日常策略 |

强调：**内容生产是执行环；策略才是作业与验收本体。**

---

## P5 · 为什么必须「策略本位」（不是发文本位）

三句够用：

1. AI 侧竞争的是**问题类被采信**，不是稿件库存。  
2. 一篇稿可以服务多条策略；一条策略必须钉死**一平台 × 一问题类**。  
3. 领导看板应看到的是：**几条策略生效/部分/未生效**，而不是本周发了几篇。

可选配图：错误路径「为发文而发文」 vs 正确路径「为策略供给而发文」。

---

## P6 · 沉淀了什么（可交接的组织资产）

汇报重点放「留下了什么」，少讲系统模块名：

| 沉淀物 | 对业务的价值 |
|--------|----------------|
| **策略对象与六元组口径** | 以后每条工作都能说清：盯哪台、问什么、发哪里、怎样算赢、用哪些料 |
| **环间交付物清单** | 上一环交什么、下一环才能开工；减少「口头说做完了」 |
| **摸底 / 复测对照机制** | 能回答「比定策前好了没有」，而不是只晒一次截图 |
| **岗位与审批规矩** | 编写/审核/技术支持边界清楚；强制沉淀可审计 |
| **知识门禁与证据层路径** | 外采与本仓同一道门；生效内容可沉淀，失败观测不冒充权威 |
| **2 个月验收尺子** | 6 条完整闭环策略 = 阶段是否做成，口径与上线一致 |
| **操作指南与周节奏** | 编辑部可按周跑，不依赖项目组口头带教 |

口播：这些是**可复制到下一轮问题类**的方法资产，不是一次性演示脚本。

## P7 · 阶段成果（当前做到哪）

用「业务可用度」表述，避免堆功能清单：

**已具备（可演示/可开干）**

- 策略从起草 → 审批 → 挂知识与任务 → 登记双渠道投放 → 判定 → 开新版本/沉淀建议，**主链已通**  
- 无诊断、无摸底，**批不成可执行**（防止空策）  
- 执行物未齐过审，**登不了已投放**（防止空投）  
- 编写与审核分账号验证过「不能自审」

**进行中 / 依赖业务投入**

- 白号池按平台补齐后，摸底与复测才算正式验收样本  
- 2 个月内跑满 **6 条真策略**（需编辑部排期与外发）  
- 生效内容按周沉淀，形成第一现场可复用证据厚度  

不要在本页展开接口、模型名、数据库。

---

## P8 · 为什么要给我们做（选型理由）

领导要的是「为何是这支队伍 / 这套方案」，建议四条，短而硬：

1. **贴业务主链，不另起炉灶**  
   对齐你们已认可的白板总流程（诊断→摸底→策略/知识/生产→分发→回流），不是外来「内容工厂」模板硬套。

2. **验收与上线同一把尺子**  
   不做「演示一套、验收一套」；缺摸底就不算过——保护的是品牌在答案层的真实进度，不是项目幻灯片。

3. **权责按传媒组织设计**  
   编辑部握审批与判定；技术部握支撑与破例终确。避免「技术替业务签字」或「业务要破例无人扛」。

4. **沉淀的是可周循环的方法，不是一次性稿件**  
   策略、对照观测、证据层、强制闸门，都能转到下一问题类、下一栏目战役；投入可复利。

可选第五句（若需对外竞品一句）：市面工具多停在「写稿/监测截图」，我们收口到**策略是否生效**。

## P9 · 边界：我们刻意不做什么（体现克制）

领导关心「会不会无限扩 scope」：

| 本期做 | 本期不做 |
|--------|----------|
| 策略闭环与判定 | 各平台代发与自动回写「已发布」 |
| 人工登记双渠道投放 | 用发文篇数代替策略验收 |
| 白号正式观测 | 把固定查询号结果当验收 |
| 生效沉淀 / 强制三闸 | 观测失败自动写进权威库 |

一句话：**先把「能不能被采信」做成可管理，再谈自动化发稿。**

---

## P10 · 2 个月目标与资源诉求

**目标**：业务可用 + **6 条策略**完整闭环（2 问题类 × 豆包/元宝/DeepSeek）。

**需要领导拍板支持的**：

1. 编辑部固定编写/审核岗与周排期（外发必须进周计划）  
2. 白号池与操作时段（技术备号、编辑操作）  
3. 问题类优先级（建议先「栏目认知」类等高频入口问题）  
4. 认可「周报看策略判定，不看发文篇数冲量」

---

## P11 · 风险与应对（各一句）

| 风险 | 应对 |
|------|------|
| 白号不足导致验收推迟 | 技术优先补齐三平台；未齐前如实标「未正式验收」 |
| 外发排期跟不上策略 | 策略数量服从渠道产能，宁少而闭环，不多而空转 |
| 急于入库破规矩 | 强制三闸；无理由不终确 |
| 把 AI 起草当成绩 | 起草可加速，**判定仍看复测** |

## P12 · 请领导定的结论（收束页）

请确认：

1. **同意**以策略闭环为阶段验收口径  
2. **同意** 6 条策略 / 2 个月为目标，并保障编辑排期与白号  
3. **同意**技术不承担日常策略业务审批，仅支撑 + 强制终确
