## 0. 一句话

内容工程不是「写更多文章」，而是让品牌知识在答案引擎里更容易被：

**找到 → 选中 → 引用 → 吸收 → 正确归因 → 可复盘**。

在本系统里，这条链路落在 Suite 主路径上，而不是另开一套 CMS。

---

## 1. 双层方法 ↔ 我们的 6 大能力

参考文档把 GEO 拆成 **全局内容资产层** 与 **单篇内容资产层**。映射如下：

| 参考方法（提炼） | 我们的能力 | 本仓落点 |
|------------------|------------|----------|
| M1 目标与边界 / M3 基线诊断 | **诊断** | `/diagnostic`：Schema、结构、Meta、外链就绪 |
| M4 实体事实库 / M5 证据原子 | **知识库** | GEOFlow KB + `pilot-demo/*/fact-cards*` |
| M2 Prompt Universe / Query Fan Out | **拓词** | `/keywords` + 探针题 `probe-questions.md` |
| M6 内容模型 / M7 结构化 / M8 分发互证 | **分发** | GEOFlow 任务 + 渠道/模板 + 中国生态 5 条正文提示词 |
| M9 可见性监控与归因 | **观测** | 可信观测 / Suite 测量（mention · citation · absent） |
| M10 治理与白帽 | **配置** + 规范 | `/admin/settings`、白帽提示词、本 SOP |

**L1–L4 提醒（汇报口径）**

- L1 被找到 ≈ 诊断 + 分发可达（代理信号，≠ 引用率）  
- L2 被引用 ≈ 知识库事实卡 + 受约束生产 + 观测闭环（核心）  
- L3 被信任 ≈ 创意/多模态可读规范（样板，不阻塞 L2）  
- L4 组织 ≈ 例会、责任制、周复盘（流程，非代码）

## 2. 演示 / 试点主路径（按 Suite 走一遍）

### 步骤 1 · 诊断（答案候选源就绪）

**目标**：确认页面能进「候选池」，结构利于抽取。

清单：

- [ ] 跑一遍网站 SEO/GEO 排查，记下 P0（FAQPage / Organization / canonical 等）  
- [ ] H1/H2 是否用用户问句，而非空洞栏目名  
- [ ] 勿把诊断里的 citation/就绪分说成「已被 AI 引用」

**产出**：优先修复清单（进 Backlog，不阻塞后续知识库导入）。

---

### 步骤 2 · 知识库（实体 + 证据原子）

**目标**：把分散资料收成可检索、可审计的事实卡。

事实卡最低字段（对齐参考「证据原子」）：

| 字段 | 说明 |
|------|------|
| fact_id | 唯一 ID |
| entity_name / aliases | 官方名 + 别名 |
| claim | 一条可验证主张 |
| evidence_source / excerpt / url | 来源、摘录、链接 |
| effective_date | 生效/核对日 |
| scope / limitations | 适用范围与限制（可写在 notes） |
| risk_level / review_status | 风险与审核状态 |
| citable_blurb（可选） | 80–150 字答案级可引用句 |

清单：

- [ ] 导入 ≥10 篇/条（演示可用 `cn-product-demo-v2`（推荐）或 `geo-demo-column`；旧 `cn-product-demo` 已不推荐）  
- [ ] 切片 + Embedding；看覆盖率/向量化率看板  
- [ ] 冲突口径（同参数两处不一致）先修再生产  
- [ ] 每条高价值主张能对应 1 条「可引用句」

**产出**：GEOFlow 知识库 + 事实卡包；演示指标见 `metrics.json`。

---

### 步骤 3 · 拓词（Prompt Universe）

**目标**：关键词 → 真实用户会问的任务集合。

清单：

- [ ] 种子词扩展为问题簇；意图分层：了解 / 比较 / 选择 / 实施 / 风险  
- [ ] 每个 P0 主题覆盖 5–20 个变体（角色、预算、行业、约束）  
- [ ] 写清「期望答案要点」与「风险词」（不能夸大的承诺）  
- [ ] 探针题与事实卡 ID 对齐（见 `probe-questions.md`）

**产出**：可移交选题 + 探针面板；不是堆砌长尾关键词。

---

### 步骤 4 · 分发（单篇工程 + 渠道互证）

**目标**：一篇页面服务一个主任务；结构可被摘要吸收。

单篇 9 步（执行摘要）：

1. Brief：目标提示、角色、期望答案、证据、风险、测量计划  
2. 一页一主任务（勿承载全部意图）  
3. **答案摘要块**：首屏 80–150 字（对象 + 价值 + 边界 + 更新时间）  
4. 骨架：问句化 H2、表格、步骤、FAQ、内链  
5. 嵌入证据原子（主张 ↔ 来源/时间/范围）  
6. 透明对比（适合谁 / 不适合谁；不攻击竞品）  
7. 实体一致 + Schema 提示（FAQPage 等，站点侧落地）  
8. 多渠道分发：官网 / 公众号 / 知乎等口径统一  
9. 登记版本与预期指标，进入观测

正文生成：优先选 GEOFlow **中国生态 5 条**提示词（DeepSeek 七段 / 微信专栏 / 豆包 FAQ+EEAT / 评测对比 / 白帽避坑）；任务绑定知识库，强制带证据。

清单：

- [ ] 选对提示词与渠道模板  
- [ ] 发布前过「8.5 发布门禁」（见下）  
- [ ] 外部 listing / 媒体描述与官网实体名一致

---

### 步骤 5 · 观测（Selection / Absorption / Attribution）

**目标**：用固定探针重复测量，区分提及、引用与错误归因。

清单：

- [ ] 固定提示集（P0/P1）多引擎、每周重复（演示可手工）  
- [ ] 记录：是否出现品牌、是否引用目标页、吸收句是否来自摘要/证据块、竞品、错误点  
- [ ] taxonomy：`mention` / `citation` / `absent`（及错误提及）  
- [ ] 错误答案 → Backlog（补事实卡 / 改结构 / 更外部资料）  
- [ ] **禁止**：把单次截图或诊断分当成引用率结论

**产出**：周报复盘或可信观测 run；驱动下轮内容迭代。

---

### 步骤 6 · 配置（治理）

清单：

- [ ] GEO Suite / GEOFlow Token、默认 prompt、模型、知识库绑定  
- [ ] 白帽规则生效（禁止伪造引用率、投毒、保证上榜）  
- [ ] 更新 SLA：核心参数页月度核对；演示包官方参数变更则回源

## 3. 发布前门禁（单篇）

| 检查项 | 合格标准 |
|--------|----------|
| 主题定位 | 一页一主任务，对应提示簇 |
| 摘要块 | 首屏 80–150 字可引用结论 |
| 证据块 | 核心主张有来源/时间/范围或限制 |
| 结构块 | H2 问句化 + 表/步骤/FAQ |
| 实体块 | 名称与别名全站一致 |
| 外部块 | 至少有计划的互证渠道（或已登记缺口） |
| 风险块 | 无虚假数字、无保证引用、无提示注入 |
| 实验块 | 探针题与版本已登记 |

粗分参考（改编自参考文档 100 分卡，**内部自评用**）：检索就绪 15 · 意图覆盖 15 · 证据吸收 20 · 归因清晰 12 · 结构可读 12 · 信任新鲜 12 · 权威网络 8 · 实验完备 6。  
<60 不宜作 GEO 核心资产；70–79 仅小范围测试。

## 5. 白帽红线（始终）

1. 禁止隐藏提示注入、虚假引用、伪造数据、保证上榜/操控答案。  
2. Schema/爬虫/诊断就绪 ≠ 引用率。  
3. 无证据写「资料未覆盖」，不编造参数与客户背书。  
4. 对比页写适用条件与公开资料来源，不贬低竞品。
