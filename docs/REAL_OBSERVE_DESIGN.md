# 真实结果观测设计说明书

> 给产品与开发评审用。说明「内容改版前后，在目标 AI 上到底发生了什么」应如何做；**本文是设计说明，不是实现任务清单**。  
> 日期：2026-07-30 · 状态：方案待评审

---

## 1. 背景与目标

今天 Suite 里的「观测」主路径，是用预先写好的剧本 JSON 把界面和漏斗讲清楚，方便演示方法。它回答的是「我们打算怎么监测」，**不是**「这几家目标 AI 此刻真实怎么答」。

真实结果观测要回答的是另一类问题：

1. **发了（或改了）内容之后**，在约定的问法、约定的 AI 平台上，**本品有没有被提到**？竞品呢？
2. 答案里**引用了哪些站点**？改版前后，引用集合有没有变？
3. 若本品没出现、或自有站点没被引用，**下一步该补什么类型的信源**（官网规格、评测、FAQ 等）？

一句话目标：**以一次内容战役为单位，做「改版前 / 改版后」成对对比，并给出可执行的信源侧建议**——而不是只报一个笼统分数。

## 2. 范围与分工

### 2.1 谁做什么

| 角色 | 负责 | 不负责 |
|------|------|--------|
| **外部采样服务** | 用白号（或等价手段）在豆包、元宝、Kimi、DeepSeek 等目标端实际提问，把答案与可拿到的引用回传 | 业务打标、前后对比、Suite 产品 UI |
| **本系统（观测服务）** | 创建战役与快照、下单采样、收结果入库、判断是否提及、整理引用、前后对比、展示与动作建议 | 维护白号池、登录态、平台反爬细节 |

前提假设：**大批量白号采样能力由外部解决**；本方案只定义「观测服务如何下单、如何收、如何用」。

### 2.2 和现有两条观测路径的区别（务必分开）

| 路径 | 实际在干什么 | 能否当作「四平台真实表现」 |
|------|----------------|---------------------------|
| **剧本观测** | 读 `geo-observe-funnel-*` 等演示数据，把监测壳界面演出来 | 否。须标明「演示·非实测」 |
| **可信观测 / API 探针**（`trust_obs_*`） | 用 OpenAI 兼容接口对模型发探针 | **否。** 那是 API 通路，不是用户眼里的豆包/元宝网页端白号采样 |
| **本文：真实结果观测** | 外部白号采样 + 本系统对比与归因 | 是（在采样方按约定回传的前提下） |

不要把四平台白号样本塞进 `trust_obs_*` 那套表里「凑合用」。语义不同，混用后演示口径与真实口径会永久搅在一起。

## 3. 核心概念

**战役（Run）**  
一次围绕固定本品、竞品、目标平台集合的作业单位。与现有 `geo_runs` 对齐：实体名、竞品名、平台列表都挂在这一层。真实观测不另起一套「作业 ID 宇宙」。

**快照**  
某一次「把整套问法在各平台采一遍」的结果集合。同一次战役里至少关心两类标签：

- **改版前（baseline）**：内容尚未按本次策略投放或尚未生效时的基准；
- **改版后（after）**：内容已投放/生效后再采一轮，用来和改版前对比。

**探针（问法）**  
发给 AI 的具体问题。以**带版本号的标准问法包**为主（团队统一维护、可复用），允许在某次快照上**少量追加自定义问法**。标准包升级要换版本键，避免把新旧问法混进同一次对比却假装同质。

**采样单元**  
「一条问法 × 一个平台 × 第几次尝试」。默认每个单元采 **1** 次；正式对比可提到 **3** 次，便于看波动。失败允许**有限次重试**，重试策略由观测服务与采样方约定（例如单单元最多再试 1～2 次），不要无限刷。

**提及**  
答案正文里是否出现本品（及可选：竞品）。第一期用**别名规则**自动打标，并允许人工改标；以后可接模型评判，但数据上要能区分「规则 / 人工 / 模型」谁标的。

**引用**  
答案指向的外部来源（URL、域名、标题等）。有的平台会给结构化引用列表，有的只有正文里的链接——两种都要能收，并标明「是结构化来的，还是从正文抽的」。

**动作建议（归因卡）**  
根据「自有域名有没有出现」「缺了哪类信源」等规则，生成给人看的建议，例如「补官网可引用规格段落」「仅有电商域时，补权威评测或 FAQ」。第一期只出建议文案，**不**自动跳进知识库去改稿。

## 4. 主流程

```text
创建/选择战役
    → 建快照（改版前或改版后）并选定问法包、平台、采样次数
    → 观测服务向外部采样方下单（带回调地址）
    → 采样方按单元回传答案（及引用）
    → 入库 → 规则打标提及 → 整理引用域名
    → 快照完成后，若战役上已有成对的改版前/后，计算对比与动作建议
    → Suite「真实采样」视图展示
```

状态上，每个快照应能区分至少：等待中、采样中、已完成、失败、部分完成（部分单元失败但仍可看已有结果）。关键节点（已下单、已收样、已打标、已对比）应能按战役或快照查到，方便排查「卡在哪一步」，而不是只能看最终自然语言结论。

## 5. 需要存的数据

建议在现有战役表之外，增加两类核心存储（名称可在实现时微调，语义如下）。

### 5.1 快照表（一次采样作业）

记录：属于哪次战役、是改版前还是改版后、用了哪一版问法包、采哪些平台、每个单元采几次、当前状态、外部采样任务号、起止时间、以及少量扩展信息。

问法列表可以嵌在快照里，也可以拆成探针明细表；无论哪种，都要能区分「标准包带来的」和「本次自定义追加的」。

### 5.2 样本表（每个采样单元一行）

记录：所属快照、问法编号、平台、第几次尝试、答案全文、引用列表、本品是否提及、竞品是否提及、匹配到的片段（便于人工核对）、打标来源（规则/人工/模型）、采样方附带的原始元数据、采样时间、若失败则错误信息。

引用列表建议存为结构化数组，单条至少包含：链接、域名、标题（可空）、引用取得方式（结构化 / 正文抽取）。

### 5.3 对比结果不必先落汇总表

「本品出现率变化、域名新增/丢失、动作建议列表」可由接口在查询时现算。第一期不必再做一张物化汇总表；若以后报表很重，再考虑缓存。

战役上已有的步骤流水（或等价日志）应能挂上真实采样相关事件，与剧本演示的步骤区分开，避免回放时搞混来源。

## 6. 与外部采样服务的约定

观测服务定义契约，采样方按契约实现。第一期可先在本系统内做一台**同契约的模拟采样器**（用固定样例答案回调），把联调跑通后再把地址换成真实采样服务。

### 6.1 下单

观测服务调用采样方的「创建任务」接口，至少带上：

- 任务编号（双方共用，后面回调要对上）；
- 回调地址（观测服务提供）；
- 平台列表；
- 问法列表（编号 + 正文）；
- 每个单元尝试次数。

鉴权、超时、限流由双方部署时再定；方案层要求：**没有回调就永远完不成快照**，因此超时扫描与有限重试下单可以放在观测服务侧，但**不要**让观测服务去轮询白号本身。

### 6.2 回调

采样方按「一条单元一条」或「一批」回传均可，字段至少包括：任务编号、问法编号、平台、第几次尝试、答案正文、引用数组（可空）、原始元数据（可空）、本条成功或失败。

若某条没有结构化引用，观测服务在入库后从答案正文抽链接补齐，并标明抽取方式。抽不到就记空，不要伪造域名。

### 6.3 缺字段与坏数据

- 缺答案且失败：记错误，单元失败，快照可进入「部分完成」。
- 引用格式不合法：尽量保留原文到元数据，引用数组记空或可解析部分，并打日志，便于采样方修契约。
- 重复回调同一单元：以最后一次成功为准，或按约定幂等键去重，避免出现率被算双倍。

附录 A 有一份示例 JSON，实现时可整理成 OpenAPI。

## 7. 提及、引用、对比与动作建议

### 7.1 提及怎么判

为战役上的本品、竞品维护别名表（含常见写法、中英文、型号简称）。对答案正文做规范化后匹配，得到是否提及，并尽量留下命中片段，方便人工一眼核对。

人工可以改标；改标后打标来源记为人工。第一期**不上**模型自动评判；表结构预留「模型」来源即可，避免以后改库。

### 7.2 引用怎么收

1. 优先采用采样方给的结构化引用；
2. 否则（或作为补充）从答案正文抽 URL，归一成域名；
3. 每条引用标明取得方式，对比时按**域名**聚合（比拼完整 URL 更稳）。

### 7.3 前后怎么比

同一战役内，把改版前与改版后的样本按「问法编号 × 平台」对齐（多次尝试可先算单元内出现率再汇总）。输出至少包括：

- 本品提及率、竞品提及率（改版前 / 后 / 差值）；
- 引用域名：新增、丢失、仍在；
- 自有域名是否出现（自有域名清单可配置，与战役实体绑定）。

### 7.4 动作建议怎么来

用规则，不写死在某个品牌演示包里。典型规则示例：

- 自有官网域名从未出现 → 建议补「官网可被引用的规格/参数段落」；
- 仅出现电商详情域、缺少评测或百科类 → 建议补「权威评测或 FAQ」；
- 本品提及上升但自有域仍缺失 → 说明「被提到了，但仍在吃别人的信源」，建议补官方可引用页。

规则类型可与现有演示策略里的信源类型枚举对齐（官网、评测、社区、电商等），便于产品和内容同学用同一套语言，但**真实观测的结论必须来自样本，不能回填剧本数字**。

## 8. 页面怎么呈现

观测页做成**两个明确分开的视图**（Tab 或等价切换）：

**演示视图**  
继续读剧本数据，界面可以精美，但必须始终标明「演示·非实测」。指标、引用、漏斗都可以是剧本写好的。

**真实采样视图**  
只绑快照与样本。最少应能：

- 选择或创建改版前 / 改版后快照，并看到状态（采样中、完成、失败、部分完成）；
- 看本品/竞品提及率、自有域引用率等**真实汇总**；
- 按问法 × 平台回放答案，看见提及标记与引用标签；
- 看见改版后相对改版前的差异条；
- 看见动作建议列表。

两个视图的默认文案、角标、空状态提示都要分开写，避免用户以为剧本里的「出现率」就是白号实测。

关于可操作性（给开发与联调的要求，用白话说清即可）：

- **状态要能查到**：不必靠人口述「采完了没有」；
- **采样要能自己触发**：不必人工把答案粘贴进系统；
- **过程要能回溯**：某次快照从下单到打标到对比，步骤可查。

## 9. 分期与明确不做

### 第一期（方案验收应能讲清、联调应能跑通）

- 契约定稿 + 模拟采样器；
- 快照 / 样本入库与状态机；
- 规则提及 + 引用双轨整理；
- 改版前/后对比与动作建议；
- Suite 真实采样视图与演示视图隔离。

第一期验收场景（自然语言）：用模拟采样跑一套标准问法、至少两个平台，分别完成改版前与改版后；页面上能看出提及率变化、域名增减，并至少出现一张说得通的动作建议；演示视图与真实视图不会把对方的数字当成自己的。

### 第二期

- 换成真实采样服务地址与鉴权；
- 驾驶舱等其它大屏若要用数，再逐步接真数（不要第一期强行全盘改装）；
- 模型辅助打标（可选、可关闭）；
- 动作建议与知识库 / 分发的「薄连接」（例如一键打开相关条目），仍不必做全自动改稿。

### 明确不做（至少第一期）

- 在本系统内自建白号池或保管平台登录态；
- 用 API 探针结果冒充四平台白号表现；
- 默认把真实采样与剧本指标画在同一套默认图表里且不加区分；
- 第一期就上模型评判当唯一真理；
- 归因建议一键自动改知识库并重新发布。

## 10. 实现时建议落点（供排期，非本文交付物）

下列仅帮助开发估工作量，**不是**本文要求立刻开工：

1. 战役域扩展接口：建快照、查状态、收回调、查样本、查对比；
2. 数据库迁移：快照表、样本表（及可选探针明细）；
3. 规则打标与动作建议模块；
4. 模拟采样器（同契约）；
5. Suite 观测页双视图。

产品侧 AI 设计约定若需同步修订，见 [`AGENT_DESIGN_8_QUESTIONS.md`](./AGENT_DESIGN_8_QUESTIONS.md) 中与观测、工具、数据链路相关的章节——真实采样路径上线前应改掉「仅方法演示、无白号」的表述边界，并写清与剧本路径的并存关系。

## 附录 A. 下单与回调示例

### 下单（观测服务 → 采样方）

```json
{
  "job_id": "3f2c8e1a-….…",
  "callback_url": "https://example.com/api/geo-runs/observe/webhook",
  "platforms": ["豆包", "Kimi"],
  "probes": [
    { "id": "q1", "text": "旅拍无人机怎么选？Mini 5 Pro 适合吗？" },
    { "id": "q2", "text": "Mini 5 Pro 和竞品比续航如何？" }
  ],
  "attempts": 1
}
```

### 回调（采样方 → 观测服务，单条示例）

```json
{
  "job_id": "3f2c8e1a-….…",
  "probe_id": "q1",
  "platform": "豆包",
  "attempt": 1,
  "status": "success",
  "answer_text": "……正文……",
  "citations": [
    {
      "url": "https://www.dji.com/…",
      "domain": "www.dji.com",
      "title": "产品页",
      "citation_source": "structured"
    }
  ],
  "raw_meta": {}
}
```

`citation_source` 取值建议：`structured`（采样方结构化）、`extracted`（观测服务从正文抽取）。

## 附录 C. 产品结论一览（评审用）

| 项 | 结论 |
|----|------|
| 目标 | 改版前后对比 + 本品提及 + 引用变化 + 信源动作建议 |
| 作业单位 | 战役下的成对快照（改版前 / 改版后） |
| 白号 | 外部采样；本系统编排与展示 |
| 引用 | 结构化优先，否则正文抽链，并标明来源方式 |
| 提及 | 近：规则 + 人工；远：可加模型；数据预留来源字段 |
| 数据 | 战役总线 + 快照/样本；不混入 API 探针表 |
| 界面 | 演示与真实双视图，口径隔离 |
| 问法 | 版本化标准包 + 少量自定义 |
| 密度 | 默认 1，正式对比可到 3；失败有限重试 |
| 归因 | 规则生成建议文案；一键改库放后期 |
| 编排 | 回调为主；状态可查；步骤可回溯 |
| 第一期 | 真契约 + 模拟采样打通闭环，再换真实采样地址 |
