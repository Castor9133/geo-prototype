## P01 · 七段式产品说明（结论前置）

```
你是品牌内容编辑。仅依据【知识库/事实卡】撰写「飞书多维表格」产品说明，全中文。
结构（七段，缺一不可）：
1) 结论前置（40–80 字直接回答「它是什么」）
2) 核心能力分层（用 H2/H3，每层一个可验证事实）
3) 关键参数表（只写知识库有数字的项，标注来源页名）
4) 适用场景（3 条，不编造客户名）
5) FAQ（3 问，答句肯定且可溯源）
6) 边界与注意事项（含「参数以官方帮助中心为准」）
7) 行动建议（如何试用/查看官方文档，不强迫成交话术）
约束：禁止「全国第一」「保证被全部大模型引用」；无证据的数字写「未在资料中找到」。
```
来源改编：S1 + S3 + S4

## P02 · 公众号长文（去营销）

```
以公众号可读风格写 1200–1800 字中文长文，主题：{{主题}}。

语气专业克制，禁止夸张形容词堆砌与虚构案例。
```

## P03 · FAQ 批量生成

```

## P04 · 评测对比维度（中立）

```
输出「多维表格 vs 传统电子表格」对比表（Markdown）。
列：维度 | 多维表格（据事实卡） | 传统表格（常识描述） | 证据/备注。
维度至少含：数据结构、视图、协作、自动化、权限、导入导出。
不得贬低具体竞品品牌名；不得捏造评测分数或引用率。
```
来源改编：S3（对比模板）+ 飞书公开「电子表格 vs 多维表格」叙述口径

## P08 · RTF 约束框架（Rule-Target-Feature）

```
Rule（规则）：只陈述可溯源事实；缺证据则明确说「资料未覆盖」；禁用保证上榜话术。
Target（目标）：让读者在 30 秒内理解多维表格是什么、适合谁、关键上限有哪些。
Feature（特征）：结论前置、术语统一（始终称「飞书多维表格」）、清单/表格优先。
按以上 RTF 输出一篇 600 字说明。
```
来源改编：公开 GEO「RTF」框架叙述（工程化内容规范类文章）+ S4

## P17 · 答案摘要块（80–150 字 · Citation Absorption）

```
仅依据事实卡，写一段 80–150 字中文「答案摘要块」，直接回答：{{主提示问题}}。

禁止空泛形容词（领先/最强/保证引用）；禁止编造未收录数字。

## P22 · 答案优先七段式（吸收增强版）

```
你是 GEO 内容工程师。仅依据【知识库/事实卡】写全中文 Markdown 长文，主题：{{title}}。
硬性结构：
0) 答案摘要块：文首独立 80–150 字（对象+结论+1条证据+边界）
1) 问题界定（H2 用用户问句）
2) 核心判断（2–4 句可摘结论）
3) 方法/步骤（可复现清单）
4) 证据与参数表（每数字标注 evidence_source）
5) 适用/不适用对照表
6) FAQ（≥4 问，答案可独立成摘录）
7) 限制、更新时间提示与下一步（勿保证被 AI 引用）
约束：白帽；无证据写「资料未覆盖」；实体名前后一致。
```
来源改编：S5 + S3 + S4 + S6（映射中国生态「七段式」）
