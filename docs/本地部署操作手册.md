# GEOrank 本地部署操作手册

> 适用仓库：[Castor9133/geo-prototype](https://github.com/Castor9133/geo-prototype)  
> 本机工作目录示例：`C:\Cursor local\GEORank`  
> 命令示例默认使用 **PowerShell**（串联用 `;`，不要用 `&&`）。  
> **切勿把真实密钥写进本文档或提交到 Git**；下文一律用占位符。

## 1. 文档目的与模式（默认裸跑）

本文说明在 Windows 本机如何：

1. **默认：本机裸跑**（无 Docker）：本机安装 PostgreSQL + Redis，用 `scripts/start-local.ps1` 起 API + worker + 带 `/api` 反代的静态前台。详见 [本地裸跑-postgres-redis.md](./本地裸跑-postgres-redis.md)。  
2. **仅静态预览**（可选）：`python scripts/serve-dist.py` — 无真实 API。  
3. **Legacy：Docker Compose**：全栈容器；需要对照 Laravel GEOFlow 时再用 `start-geo-suite.ps1 -UseCompose`。

| 对比项 | 本机裸跑（默认） | 仅静态预览 | Compose（legacy） |
|---|---|---|---|
| 前置 | Python 3 + 本机 PG/Redis | Python 3 | WSL2 + Docker Desktop |
| 启动 | `.\scripts\start-local.ps1` | `python scripts/serve-dist.py` | `docker compose …` / `-UseCompose` |
| 前台 | http://localhost:3009（反代 /api） | http://127.0.0.1:3009 | http://localhost:3009 |
| API | http://localhost:8000 | mock / 无 | 容器内 8000 |
| Suite / 内容引擎 | **可用**（`CONTENT_BACKEND_MODE=native-python`） | 部分 UI | 可用；Flow 需另起 |
| GEOFlow | **演示不需要** | 不需要 | 可选 `-WithGeoFlow` |

**怎么选：**

- 日常开发与演示 → **本机裸跑**（推荐）。  
- 只想扫一眼静态 UI → 仅静态预览。  
- 对照 Laravel / 旧联调 → Compose legacy，并设 `CONTENT_BACKEND_MODE=legacy-flow`。  
- 改 Next.js 源码（`apps/web`、`apps/admin`）→ 栈起来后加 `pnpm`（见第 7 节）。

## 3. Windows 前置：WSL2、Docker Desktop、镜像加速

以下每步格式：**目的 / 操作 / 验证 / 失败常见原因**。标有「管理员」的步骤需要 **以管理员身份运行**（UAC 提升）。

内容引擎（`/admin/content-engine`）须管理员登录；未登录会跳到 `/admin/?returnUrl=…`，登录后回跳。详见 [m1-acceptance-checklist.md](./m1-acceptance-checklist.md)。

### 3.1 启用 WSL2（管理员）

- **目的**：Docker Desktop 在 Windows 上依赖 WSL2 后端。只下载安装包却未装 WSL 时，引擎无法启动。  
- **操作**（任选其一）：

  **方式 A — 仓库辅助脚本（管理员 CMD）：**

  ```bat
  cd /d "C:\Cursor local\GEORank"
  scripts\setup-windows-docker.cmd
  ```

  脚本会启用 `Microsoft-Windows-Subsystem-Linux`、`VirtualMachinePlatform`，并执行 `wsl --install --no-distribution`。

  **方式 B — PowerShell（管理员）：**

  ```powershell
  dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
  dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
  wsl --install --no-distribution
  ```

  首次安装后按提示 **重启 Windows**。

- **验证：**

  ```powershell
  wsl --status
  wsl -l -v
  ```

  应能看到 WSL 已安装；不必强制安装某个 Linux 发行版（`--no-distribution` 即可满足 Docker）。

- **失败常见原因：**  
  - 未提权 / UAC 取消 → 功能未启用。  
  - 未重启 → 状态仍提示需安装。  
  - 公司策略禁用虚拟化 / BIOS 未开虚拟化。  
  - Docker 日志出现 `DockerDesktop/Wsl/NotInstalled` → 回到本步，装完并重启后再开 Docker。

### 3.2 安装并启动 Docker Desktop

- **目的**：提供 Docker Engine 与 `docker compose`。  
- **操作：**  
  1. 安装 Docker Desktop for Windows（官方安装程序）。  
  2. 安装完成后启动 Docker Desktop，确认设置使用 **WSL2** 引擎。  
  3. 等待托盘图标变为 Running。  
- **验证：**

  ```powershell
  docker version
  docker compose version
  docker info
  ```

  `Server` 段应有版本信息，无 `Cannot connect to the Docker daemon` 类错误。

- **失败常见原因：**  
  - WSL 未就绪（见 3.1）。  
  - 安装后未登录/未完成首次引导。  
  - Hyper-V / 虚拟化冲突（按 Docker 官方排障）。

### 3.3 配置 Docker Hub 镜像加速（国内强烈建议）

- **目的**：避免直接拉 Docker Hub 超时。  
- **操作：** 编辑用户目录 `C:\Users\<你的用户名>\.docker\daemon.json`（没有则新建），示例：

  ```json
  {
    "registry-mirrors": [
      "https://docker.1ms.run"
    ]
  }
  ```

  可按公司可用源追加多个 mirror。保存后 **重启 Docker Desktop**。

- **验证：**

  ```powershell
  docker info
  ```

  输出中应出现 `Registry Mirrors` 列表。可再试：

  ```powershell
  docker pull redis:7.4.5-alpine
  ```

- **失败常见原因：**  
  - JSON 语法错误导致 Docker 无法启动 → 用编辑器校验后重开。  
  - 镜像源不可用 → 更换公司推荐源或 VPN。  
  - 改完未重启 Docker。

## 4. 获取代码与配置 `.env`

### 4.1 获取代码

```powershell
# 若尚未克隆
git clone https://github.com/Castor9133/geo-prototype.git "C:\Cursor local\geo-prototype"
Set-Location "C:\Cursor local\GEORank"
```

本机已有克隆则直接进入目录即可。

### 4.2 复制并填写 `.env`

```powershell
Set-Location "C:\Cursor local\GEORank"
Copy-Item .env.example .env
```

用编辑器打开 `.env`，至少替换下列占位符（示例值仅为格式示意）：

```env
DEBUG=true
SECRET_KEY=<随机长字符串>
SETTINGS_ENCRYPTION_KEY=<另一组随机长字符串>
JWT_SECRET=<再一组随机长字符串>
PUBLIC_BASE_URL=http://localhost:3009

POSTGRES_PASSWORD=<强密码>
NEO4J_PASSWORD=<强密码>

# Compose MinIO 容器读取这对；后端也认这对（及 MINIO_USER/MINIO_PASSWORD 别名）
MINIO_ACCESS_KEY=<访问密钥>
MINIO_SECRET_KEY=<秘密密钥>
MINIO_USER=<与 ACCESS_KEY 相同即可>
MINIO_PASSWORD=<与 SECRET_KEY 相同即可>

# 可选：固定管理员种子密码，便于本机反复登录
GEORANK_SEED_ADMIN_PASSWORD=<本机自用强密码>

# 可选：先在环境变量配 LLM；也可启动后在后台配置 API 池
# LLM_API_KEY=sk-xxxx
# LLM_BASE_URL=https://your-openai-compatible-endpoint/v1
# LLM_MODEL=gpt-4o-mini
```

本地开发端口（与 `docker-compose.dev.yml` 一致，可写入 `.env` 或系统环境变量）：

```env
GEORANK_FRONTEND_PORT=3009
GEORANK_API_PORT=8000
```

Traefik 默认还会占用宿主机 **80 / 443**（`GEORANK_HTTP_PORT` / `GEORANK_HTTPS_PORT`）。若本机 80 已被占用或需要管理员绑定特权端口，可改为例如：

```env
GEORANK_HTTP_PORT=8080
GEORANK_HTTPS_PORT=8443
```

本地日常访问前台/API 主要用 **3009 / 8000**，不必依赖 80。

### 4.3 生成随机密钥示例（PowerShell，勿把输出提交）

## 5. 完整 Docker 部署与健康检查

> **不要中断**已在进行的 `docker compose ... up -d --build`。另开终端做检查即可。

### 5.1 启动（最短路径）

```powershell
Set-Location "C:\Cursor local\GEORank"
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

首次会拉取基础镜像并 build `api` / `worker` / `beat` / `crawler` / `migrate`，耗时可能很长。

### 5.2 启动链路说明

1. `postgres`、`redis` 等到健康。  
2. 一次性服务 `migrate` 执行 Alembic 到 head，成功后状态为 **`Exited (0)`（正常）**。  
3. 其后 `api`、`worker`、`beat`、`crawler`、`frontend` 等才启动。  
4. `api` 健康检查：容器内 `http://localhost:8000/api/health`。  
5. `docker-compose.dev.yml` 把前台映射到 `127.0.0.1:3009`，API 到 `127.0.0.1:8000`。

详情见 [数据库迁移与启动](./database-migrations.md)。

### 5.3 健康检查

```powershell
Set-Location "C:\Cursor local\GEORank"
docker compose -f docker-compose.yml -f docker-compose.dev.yml ps
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs migrate --tail 50
Invoke-WebRequest -Uri http://127.0.0.1:8000/api/health -UseBasicParsing
Invoke-WebRequest -Uri http://127.0.0.1:3009/ -UseBasicParsing
```

期望：

- `migrate` → `Exited (0)`  
- `api` → `healthy`（或至少 Up 且 health 通过）  
- `/api/health` → HTTP 200  
- 浏览器打开 http://127.0.0.1:3009 能看到前台  

### 5.4 写入种子用户与示例数据

迁移成功后执行（会打印管理员密码；若 `.env` 已设 `GEORANK_SEED_ADMIN_PASSWORD` 则使用该值）：

```powershell
Set-Location "C:\Cursor local\GEORank"
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm api python -m app.scripts.seed
```

控制台会输出类似：

- 管理员：`admin@georank.com` / `<密码>`  
- 演示用户：`demo@neuralpath.ai` / `<密码>`  

可将管理员密码自行保存在本机 **未跟踪文件**（例如 `.local-admin-password.txt`，已在 `.gitignore`），**禁止提交仓库**。

### 5.5 升级代码后

```powershell
Set-Location "C:\Cursor local\GEORank"
git pull
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm migrate
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

## 6. 演示模式（无 Docker）

适用于：WSL/Docker 尚未就绪，只想浏览静态站与公司目录演示数据。

### 6.1 前提

- 已安装 Python 3  
- 仓库内存在 `dist/`（开源仓自带静态前台）  
- **端口 3009 未被占用**（若之前开过 `python -m http.server` 或其他进程，先结束）

### 6.2 操作

```powershell
Set-Location "C:\Cursor local\GEORank"
python scripts\serve-dist.py
```

浏览器打开：http://127.0.0.1:3009  

### 6.3 能力边界

- 公司目录等走脚本内 mock 数据。  
- **登录、真实诊断、Celery 任务、后台改库、API 池保存等到真实后端的功能不可用。**  
- 终端会提示 demo mode，直到 Docker/WSL 后端就绪。

### 6.4 停止

在运行该脚本的终端按 `Ctrl+C`。

## 8. 首次登录、后台与 API 池（LLM）

### 8.1 打开后台

完整部署且已 seed 后：

1. 浏览器打开前台：http://127.0.0.1:3009  
2. 管理后台静态页：http://127.0.0.1:3009/admin/ （或仓库 `dist/admin/` 对应路由）  
3. 使用种子管理员：  
   - 邮箱：`admin@georank.com`  
   - 密码：`.env` 中 `GEORANK_SEED_ADMIN_PASSWORD`，或 seed 日志 / `.local-admin-password.txt`

演示模式下登录会失败或无真实会话——属预期。

### 8.2 配置 API 池

路径：后台 → **系统设置** → **API 配置** 页签。

可配置：

- 多个兼容 OpenAI 格式的 Provider（Base URL、模型名、API Key）  
- 连通性测试  
- 轮询 / 故障转移策略  
- Key 加密存储（列表不回显明文）

也可先在 `.env` 填写 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` 做环境级默认；后台池适合团队多供应商与轮换。

`ALLOW_PRIVATE_LLM_PROVIDER_URLS=false`（默认）时禁止指向私网地址的 Provider（防 SSRF）。仅受信内网自建模型可改为 `true`，并收紧网络暴露面。

### 8.3 AI 功能验收（简要）

在 Key 可用后抽样：

- GEO 问答或拓词是否返回模型内容（而非纯本地 fallback）  
- Provider「测试」按钮是否成功  
- 失败时看 `api` / `worker` 日志（见第 9 节）

## 9. 日常启停与排障

### 9.1 启停（完整栈）

```powershell
Set-Location "C:\Cursor local\GEORank"

# 启动
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d

# 停止（保留 volumes 数据）
docker compose -f docker-compose.yml -f docker-compose.dev.yml stop

# 停止并移除容器（默认不删 named volumes，数据仍在）
docker compose -f docker-compose.yml -f docker-compose.dev.yml down
```

**危险操作（会丢库）：** `down -v` 会删除 volumes，仅在明确要清空本机数据时使用。

### 9.2 常用日志

```powershell
Set-Location "C:\Cursor local\GEORank"
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs -f api --tail 100
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs -f worker --tail 100
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs migrate --tail 100
```

### 9.3 排障表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| Docker 无法启动，日志 `Wsl/NotInstalled` | 未装/未启用 WSL2 | 第 3.1 节，重启后再开 Docker |
| `docker pull` 超时 | 直连 Hub 慢 | 第 3.3 节镜像加速 |
| `migrate` 非 0 退出，API 不起 | 迁移失败或旧库无 `alembic_version` | 看 migrate 日志；对照 [database-migrations.md](./database-migrations.md)，勿对生产盲目 `stamp` |
| 3009 打不开 | 未起 frontend / 端口被演示脚本占用 | `docker compose ps`；结束占用 3009 的 Python 进程后再起 Compose |
| 8000 无响应 | api 未 healthy / 未叠加 dev compose | 确认使用了 `docker-compose.dev.yml`；查 api 日志 |
| 登录失败 | 未 seed / 密码不对 / 仍处演示模式 | 跑 seed；核对本机密码文件；确认访问的是 Compose 前台而非仅 `serve-dist.py` |
| AI 无响应或报错 | 未配 Key / Base URL 错 / 额度用尽 | 后台 API 池测试；检查 `LLM_*`；看 worker 日志 |
| MinIO 相关错误 | `.env` 只写了 `MINIO_USER` 而 Compose 读 `MINIO_ACCESS_KEY` | 两套变量写成相同值 |
| 端口 80 冲突 | Traefik 默认 80 | 设置 `GEORANK_HTTP_PORT=8080` 后重建 |
| 本机改 `.env` 不生效 | 容器未重建/未重启 | `up -d` 或 `up -d --force-recreate api worker beat crawler` |

### 9.4 需要管理员权限的步骤（汇总）

| 步骤 | 是否管理员 |
|---|---|
| 启用 WSL / DISM 功能 / `wsl --install` | **是** |
| 安装 Docker Desktop（安装程序） | 通常 **是** |
| 编辑用户目录 `daemon.json`、跑 compose、pnpm、演示脚本 | **否**（普通用户） |
| 绑定宿主机 80/443 | 视系统策略；冲突时改用非特权端口更省事 |

## 10. 生产向补充（非本机必做）

本地开发一般到第 5–8 节即可。若部署到服务器：

- `DEBUG=false`，`PUBLIC_BASE_URL` 使用 HTTPS 正式域名。  
- `TRUSTED_HOSTS` 仅保留正式域名与健康检查所需主机名。  
- Traefik：配置可信证书 / ACME 或外部 LB 做 TLS；仓库模板预留 `websecure`。  
- 密钥与真实 API Key 仅放服务器密钥管理或环境变量，**不要提交 Git**。  
- 遵守 [公开内容边界](./public-content-boundary.md)：私有教程、客户数据、真实 Key 不进开源发布。
